# 시장 평가 정보(밸류에이션) 제품 범위 설계

작성일: 2026-09-27 · 성격: **제품 범위 설계(문서만).** 코드·화면·테스트·fixture·검증기·AI 프롬프트·생성 로직은 바꾸지 않았다. 구현 방법(데이터 소스, 테이블, 계산 위치, 화면 배치)은 정하지 않았다. 결정은 [D-65](../decisions/D-60-D-99.md)로 남겼다.

## 0. 목적과 결론 요약

- **질문**: D-64로 밸류에이션은 "투자 전 참고 정보"가 되었다. 그렇다면 어떤 지표를, 무엇과 비교해, 어디까지 보여 주는가. AI는 어디까지 관여하는가. 기존 재무 분석과는 어떤 관계인가.
- **근거 문서**: [decisions/README.md](../decisions/README.md) D-06·D-15·D-22·D-33·D-35·D-37·D-41·D-47·D-49·D-60~D-64, [product.md](../product.md) §4·§10·§12, [architecture.md](../architecture.md) §4.2·§6·§10, [spec/](../README.md) §3.6·§3.9·§4·§7.2, [목적 확장 검토](investment-reference-purpose-review.md).
- **표시**: [확인](문서로 검증), [판단](검토 의견), [미확인](확인하지 못한 외부 사실).

**결론**

1. **지표는 세 개로 시작한다**: 시가총액, PER, PBR. 배당수익률은 배당 정보를 설계한 뒤 같은 규칙으로 더한다. PSR·EV/EBITDA·PCR·PEG·주당 지표 단독 표시는 넣지 않는다.
2. **비교는 "무엇으로 계산했나"와 "두 기업의 실제 값"까지만 한다.** 입력값(시가총액·순이익·자본)과 그 기간·기준일을 나란히 보인다. 기업 비교 페이지에서는 두 기업의 값을 나란히 둔다(§11에서 수정). 업종·시장 평균, 과거 PER, 여러 기업 표와는 비교하지 않는다. 시장 평가의 **변화**는 비율의 추이가 아니라 구성 요소(주가 차트, 재무 추이)로 보여 준다.
3. **AI는 시장 평가 정보에 관여하지 않는다.** 어떤 분석 종류의 입력에도 넣지 않는다. 지표의 뜻은 사람이 검토한 정적 콘텐츠가 설명한다.
4. **재무 분석과는 "같은 원천, 다른 묶음"이다.** 분모는 재무 원천에서 오지만, 재무 지표의 네 묶음(D-47)에 넣지 않고 시세 모듈의 "시장 평가" 묶음에 둔다. 신호·재무 쉬운 설명·지표 보기의 판정 자리는 그대로다.

## 2. 어떤 지표가 필요한가

판단 기준은 D-47과 같다. **투자 전에 새 정보를 주는가**, 이미 보이는 값을 다른 분모로 반복하는가.

| 후보 | 사용자가 얻는 답 | 판단 | 이유 [판단] |
|---|---|---|---|
| 시가총액 | 시장에서 이 회사 주식 전체가 얼마에 거래되나(회사의 시장 규모) | **포함** | 규모 사실. 다른 지표의 분자다 |
| PER | 1년 이익의 몇 배 가격에 거래되나 | **포함** | 가격과 이익을 잇는 가장 기본적인 참고 수치. 재무에서는 알 수 없는 새 정보다 |
| PBR | 장부상 자본의 몇 배 가격에 거래되나 | **포함** | 가격과 자본을 잇는다. 적자라 PER이 없는 기업(ROE 음수 37%, D-47 확인)과 금융형에서 특히 쓰인다 |
| 배당수익률 | 지금 가격에 사면 최근 배당이 가격의 몇 %인가 | **조건부 포함** | 배당금 데이터가 아직 설계 전이다(주주환원 영역, 목적 확장 검토 §3 C-1). 설계 뒤 PER과 같은 규칙으로 더한다 |
| 주가·등락률·거래량 | 가격 자체와 움직임 | 기존 설계 | 시세 모듈 차트·일일 변동(architecture.md §6.2)이 이미 다룬다 |
| PSR(시가총액 ÷ 매출) | 매출의 몇 배인가 | 제외 | 시가총액과 매출이 이미 보인다. 지표를 늘리면 포털식 목록이 된다. 적자 기업의 대안이라는 쓰임은 재검토 조건으로 둔다 |
| EV/EBITDA | 부채까지 합친 기업가치 ÷ 현금성 이익 | 제외 | EBITDA에 감가상각 세부 항목이 필요하다. D-48은 현금흐름 세부 항목을 쓰지 않는다 |
| PCR(시가총액 ÷ 영업현금흐름) | 현금흐름의 몇 배인가 | 제외 | 현금흐름은 부호가 자주 바뀐다(D-48 확인: 연간 33% 음수). 계산 불가가 많고 PER과 겹친다 |
| PEG | PER ÷ 이익 성장률 | 제외 | 보통 성장 전망치를 쓴다. 예측이다(product.md §10) |
| EPS·BPS 단독 표시 | 주당 이익·자본 | 제외(D-47 유지) | PER·PBR의 입력으로서의 뜻은 결정 3의 입력값 표시가 대신한다. 주당 지표 자체는 주식 수·희석 영역에서 다시 본다(D-47 후속) |
| 52주 최고·최저 대비 위치, 고점 대비 하락률 | 지금 가격이 과거 구간 어디쯤인가 | 제외 | 과거 구간 속 위치는 "싸졌다"로 읽힌다(D-63 기준 (2)). 가격의 역사는 차트가 이미 보인다 |
| 외국인 지분율·공매도·수급 | 누가 사고파나 | 제외 | 기업이 아니라 거래 주체의 정보다. 라이선스도 없다 |
| 컨센서스 목표가·예상 PER | 증권사 전망 | 제외(유지) | 예측(product.md §10, architecture.md §12.1) |
| 시가총액 순위 | 규모가 몇 번째인가 | 이번 범위 밖 | 규모 사실이지만 필요성이 확인되지 않았다. 제안이 나오면 규모 사실로 따로 판단한다 |

## 3. 계산의 뜻 (제품 의미)

어떻게 계산하는지(데이터 소스, 코드 위치)는 정하지 않는다. **숫자가 무엇을 뜻하는지**만 정한다.

| 항목 | 뜻 | 이유 |
|---|---|---|
| 원칙 | 분자와 분모는 **같은 주주 몫**을 가리킨다 | 시가총액은 주주가 가진 주식의 가격이다. 분모도 그 주주에게 속한 이익·자본이어야 비율이 뜻을 가진다 |
| 가격 | 기준일(가장 최근 거래일) 종가 | 일별 시세만 있다(D-22). 기준일을 항상 보인다 |
| 시가총액 | 상장된 모든 주식 종류(보통주·우선주)의 종가 × 주식 수의 합. 자기주식처럼 이익·자본을 나눠 받지 않는 주식을 뺄지는 위 원칙을 따른다 | 우선주는 보통주 기업에 속한다(architecture.md §4.3). 주식 수 데이터의 출처와 정밀한 산출은 [미확인]이며 구현 설계에서 정한다 |
| PER의 이익 | **최근 사업연도의 연간 순이익**. 연결 재무제표 기업은 지배기업 소유주 귀속분 | 최근 4분기 합산은 보고서를 넘나드는 계산이다(D-33·D-35·D-47이 뺐다). 연간 한 벌 안의 값만 쓴다. 대가: 최대 약 15개월 전 실적이므로 기간을 반드시 보인다 |
| PBR의 자본 | **최신 기간 말 자본총계**. 연결 기업은 지배기업 소유주 귀속분 | 자본은 시점 값이라 최신 분기말을 쓸 수 있다. PER과 기간이 다르므로 값마다 자기 기간 라벨을 붙인다(D-62 결정 2) |
| 재무 기준 | 시계열 기준(연결 우선, D-37)과 같다 | 재무 섹션과 같은 기준이어야 한다 |
| 지배주주 기준과 ROE의 관계 | ROE는 D-47대로 비지배 포함이다. PER·PBR의 분모는 지배주주 귀속이라 재무 섹션의 "당기순이익"과 값이 다를 수 있다 | 같은 이름으로 다른 값을 보이면 안 된다(D-62 결정 1). 입력값은 "지배주주 순이익"처럼 **다른 이름**으로 보인다. 혼란이 확인되면 D-47의 지배주주 전환 재검토 조건을 쓴다 |

### 계산하지 않는 경우 (값 대신 사유)

| 경우 | PER | PBR | 시가총액 |
|---|---|---|---|
| 기준 순이익 ≤ 0 | 계산하지 않음("최근 연간 순이익이 0 이하") | — | — |
| 기준 자본 ≤ 0 | — | 계산하지 않음 | — |
| 지배주주 귀속 값을 확인할 수 없음 | 계산하지 않음. 비지배 포함 값으로 대신하지 않는다 | 같음 | — |
| 재무 통화가 원화가 아님 | 계산하지 않음. 환산하지 않는다(D-41) | 같음 | 보인다 |
| 12개월이 아닌 회계연도 | 계산하지 않음(D-33) | 해당 없음 | — |
| 금융형 | **계산한다** | **계산한다** | 보인다 |
| 주식 수·시세 기준일이 확인되지 않음 | 계산하지 않음 | 같음 | 보이지 않음 |

- 금융형을 계산하는 이유: 영업이익률·부채비율을 쓸 수 없는 금융형에서 PBR은 가장 많이 참고되는 값이다 [판단]. 현금흐름(D-48)과 달리 순이익·자본의 뜻이 흐려지지 않는다.
- 사유는 D-60처럼 값 자리에 둔다. 빈칸이나 "N/A"로 두지 않는다.
- 최신 재무가 늦으면(`FIN_DATA_STALE`) 데이터 한계 표시(D-43)를 함께 보인다.

## 4. 어떤 비교가 필요한가

| 비교 | 판단 | 이유 [판단] |
|---|---|---|
| **입력값 병기**: 시가총액, 기준 순이익·자본과 그 기간, 주가 기준일 | **한다** | "무엇으로 계산했나"가 참고 정보의 근거다(D-49). 사용자가 스스로 다시 계산할 수 있다 |
| 같은 기업의 과거 PER·PBR(추이, 전년 같은 날, 5년 평균·밴드) | 하지 않는다 | 과거 구간 속 위치는 "싸졌다·비싸졌다"로 읽힌다(D-63 기준 (2)) |
| 업종·시장 평균·중앙값 대비 | 하지 않는다 | 가치 판정 그 자체다(D-49) |
| 두 기업 나란히(기업 비교 페이지) | **한다**(2026-09-27 재검토로 수정, §11). 시가총액·PER·PBR과 각자의 입력값을 나란히 둔다. 차이·대소·강조·정렬은 두지 않는다 | 첫 안은 "서비스가 비교 쌍을 고른 가격 비교"라며 뺐다. 재검토에서 이 전제가 사실과 달라 바꿨다 |
| 여러 기업을 한 표에(기업 상세의 경쟁사 목록 등) | 하지 않는다 | 3~5개 값이 모이면 사실상 업종 분포(기준선)가 된다 |
| 순위·목록(저PER 상위, 저PBR 종목) | 하지 않는다 | 서비스가 고른 조건 묶음은 추천이 된다(목적 확장 검토 §3 F) |
| 역수(이익수익률), 금리·채권 대비 | 하지 않는다 | 투자 매력 비교다 |

### 시장 평가의 "변화"는 구성 요소로 본다

- 제품의 중심 관점은 변화다(product.md §1). 그러나 PER의 변화는 가격이 움직였거나 이익이 바뀐 결과일 뿐, 따로 일어나는 변화가 아니다.
- 그래서 비율의 추이는 만들지 않는다. **가격의 변화는 주가 차트와 일일 변동이, 이익·자본의 변화는 재무 추이와 신호가** 이미 보여 준다.
- 사용자는 "PER이 왜 이런가"를 두 구성 요소의 변화로 이해한다. 이것이 데이터를 연결하는 방식이다(product.md §11-2).

## 5. AI 설명에 포함할 범위와 포함하지 않을 범위

| 구분 | 범위 |
|---|---|
| **포함하지 않음** | 시가총액·PER·PBR·배당수익률의 값·수준·변화. 어떤 분석 종류(기업 이해, 재무 쉬운 설명, 향후 전망, 경쟁사 비교, 일일 변동)의 입력에도 넣지 않는다. 출력에서 이 지표를 언급하지 않는다 |
| **포함하지 않음** | 가격과 가치를 잇는 서술: "시장이 높게 평가", "이익에 비해 가격이 높다", "주가가 실적을 반영하지 못했다", "재평가" |
| **포함하지 않음** | 기업 이해가 요약하는 사업보고서 원문에 주가·시가총액 서술이 있어도 옮기지 않는다 |
| **유지(기존)** | 일일 변동은 기존 설계대로 가격의 움직임과 같은 날의 근거만 설명한다(spec/analyses.md §4.5). 수준(싸다·비싸다)은 이미 금지다(§7.2) |
| **AI가 아닌 곳이 맡음** | 지표의 뜻("PER은 이익의 몇 배에 거래되는지예요")과 해석 참고("업종·성장 기대·일회성 이익에 따라 크게 달라서 높고 낮음만으로 좋고 나쁨을 말할 수 없어요")는 **정적 콘텐츠**다. 기업마다 생성하지 않는다. AI 초안 + 사람 검토(spec/analyses.md §10) |

이유 [판단]
- 시장 평가 수치에 문장이 붙으면 거의 모든 문장이 평가로 읽힌다. "PER이 5배예요"도 맥락 문장이 붙는 순간 "싸요"가 된다. 수치와 입력값, 정적 정의만으로 충분히 이해할 수 있다.
- 코드가 판정할 규칙도 없다(신호 금지, D-49). 판정이 없는 곳에서 AI가 설명하면 AI가 판정하게 된다(D-06).
- 비용이 들지 않는다. 가격이 매일 바뀌므로 넣으면 매일 재생성된다(D-08의 이유와 같다).
- 시가총액도 넣지 않는다. 규모는 AI 입력에 이미 있는 매출로 설명할 수 있다. 시가총액을 넣으면 "시장이 크게 평가하는 회사"처럼 평가로 흐른다. D-64 결정 5에서 미룬 것을 여기서 정한다.

현재 코드와의 관계 [확인]: 재무 쉬운 설명은 이미 PER·PBR·주가·시가총액·배당을 금지 주제로 둔다(spec/financial-explain.md §4.4.7 규칙 9). 이번 결정으로 바뀌는 코드는 없다. 아직 구현하지 않은 분석 종류(기업 이해·향후 전망·경쟁사 비교)를 설계할 때 같은 제약을 입력·검증에 넣는다.

## 6. 기존 재무 분석과의 관계

| 기존 요소 | 관계 | 바뀌는 것 |
|---|---|---|
| 재무 지표 네 묶음(D-47), 지표 보기(spec/signals-financial.md §3.9) | 시장 평가는 **다섯 번째 묶음이 아니다**. 네 묶음은 기업 자체의 실적·상태이고, 시장 평가는 시장 가격과의 관계다. 시세 모듈 쪽의 별도 "시장 평가" 묶음에 둔다 | 없음 |
| 지표 보기의 구성(정의·현재 값·비교·큰 변화 여부·해석 참고·계산하지 않음) | 시장 평가도 정의·현재 값(+입력값)·해석 참고·계산하지 않음을 쓴다. **비교 자리와 큰 변화 여부(판정) 자리는 두지 않는다.** 판정 규칙을 만들지 않기로 한 지표라 D-60의 "판정 규칙 없음"도 보이지 않는다 | 없음(적용 범위만 정함) |
| 재무 원천·요약(D-32·D-33·D-37) | 분모는 같은 원천에서 온다. 지배주주 귀속 값은 지금 저장하지 않는 값이라 데이터 확보는 구현 설계의 일이다 [미확인: 주요계정 API는 지배주주 분리를 주지 않음(D-14 확인 계정 목록)] | 없음(지금) |
| 표시 규칙(D-41·D-62) | 금액 표기, 기간 라벨, "한 값 한 표시"를 그대로 따른다 | 없음 |
| 신호(D-15·D-35) | 시장 평가로 신호를 만들지 않는다(D-49). 기존 신호도 시장 평가를 쓰지 않는다 | 없음 |
| 재무 쉬운 설명(D-38~D-59) | 입력·출력·검증 그대로. 시장 평가 수치를 옆에 두어도 설명 문장은 그 수치를 말하지 않는다 | 없음 |
| 향후 전망의 확인 지표 | 시장 평가를 확인 지표로 쓰지 않는다. "PER을 지켜보세요"는 가격 판단을 권하는 것이 된다 | 없음(제약 명시) |
| 데이터 한계(D-43) | 최신 재무가 늦으면 시장 평가의 분모도 오래된 것이다. 같은 데이터 한계 표시를 보인다 | 없음 |

## 7. 화면에서 지켜야 할 의미 (배치는 정하지 않음)

- 시장 평가 묶음에는 코드가 고정 문구를 붙인다. 뜻: "시장 가격으로 계산한 참고 수치이며, 서비스가 기업의 가치를 평가한 것이 아닙니다." 문구는 화면 설계·면책 검토에서 정한다(목적 확장 검토 §4).
- 출처를 둘 다 보인다: 시세 소스(기준일)와 재무 출처 공시(기간).
- 색·화살표·강조로 높고 낮음을 표시하지 않는다(spec/signals-financial.md §3.9의 "평가를 덧씌우지 않는다"와 같다).
- AI 적용 대상과 무관하게 시세가 있는 모든 ACTIVE 기업에 보인다. AI가 관여하지 않기 때문이다.
- 홈·목록 화면에 시장 평가 수치로 정렬·선별한 목록을 두지 않는다.

## 11. 재검토: 기업 비교 페이지의 PER·PBR (2026-09-27)

첫 안(§4)은 기업 비교 페이지에서 PER·PBR을 빼고 시가총액만 나란히 두었다. 이 제한이 제품 목적과 기존 결정에 비추어 정말 필요한지 다시 봤다.

### 11.1 구분해야 할 두 가지

| | 판단 대행 (하지 않음) | 참고 정보 (할 수 있음) |
|---|---|---|
| 무엇 | 서비스가 두 값의 **관계를 만들거나 판정**한다 | 서비스가 두 기업의 **실제 값을 각자의 사실로** 둔다 |
| 예 | "A가 B보다 PER이 낮다", "B의 절반", 낮은 쪽 초록색, PER 순 정렬, 두 값의 평균선, "상대적으로 저평가" | A: PER 8.2배(2025년 연간 지배주주 순이익 기준, 9월 26일 종가) · B: PER 15.4배(같은 기준일) — 끝 |
| D-63 기준 | (1) 평가어, (2) 평가를 함축하는 기준선, (3) 결론으로 합치기 | 사실과 산술 값 |

### 11.2 첫 안의 이유 점검 [확인]

| 첫 안의 이유 | 점검 | 결과 |
|---|---|---|
| "서비스가 비교 쌍을 고른 가격 비교가 된다" | 비교 페이지는 `/compare/A-vs-B`로 **사용자가 임의의 두 기업을 여는 곳**이다(architecture.md §6.1, D-11의 "그 외 쌍은 코드가 만든 데이터 비교"). 확정 경쟁사 쌍도 가격이 아니라 **사업 유사성**으로 정해진다(D-26, 기업 이해의 경쟁사 선택). 서비스가 가격 비교를 위해 쌍을 고르는 경우는 없다 | 사실과 다르다 |
| D-49 "업종·시장 평균, 과거 구간과 비교하지 않는다" | 금지 대상은 **기준선**(평균·분포·과거 밴드)이다. 두 기업의 값은 기준선이 아니다. 평균이 없으면 "평균보다 낮다"는 판정이 생기지 않는다 | 충돌 없음 |
| D-63 기준 (2) "평가를 함축하는 비교 기준" | 적힌 예는 "가격 지표의 업종·시장 평균 대비, 과거 구간 속 위치"다. 두 기업 나란히는 목록에 없고, 기준선을 만들지 않는다 | 충돌 없음 |
| D-47의 선례 | 재무 지표는 동종업계 중앙값을 "참고 값"으로 나란히 두는 것까지 허용하고 평가어만 금지했다 | 두 기업 나란히는 이보다 약하다 |
| 제품 목적(D-63), product.md §2 | 두 값은 각 기업 상세에 이미 보인다. 비교 페이지에서만 빼면 판단 대행을 막는 효과는 없고, 사용자가 두 페이지를 오가게 만든다("정보의 분산") | 제한이 목적에 어긋난다 |

[판단] 첫 제한은 필요하지 않다. 위험은 두 값을 보이는 데서가 아니라, 서비스가 두 값의 관계를 말하는 데서 생긴다. 그래서 관계를 만드는 표현을 막는 조건으로 바꾼다.

### 11.3 남는 위험과 조건

| 위험 | 조건 (D-65 결정 5-1) |
|---|---|
| 배치·강조가 한쪽을 권하는 것처럼 보임 | 차이·배수·대소 어휘·강조·값 순 정렬·평균선 없음. 순서는 URL 정규화(종목코드) 순 |
| 기준이 다른 두 값을 같은 것처럼 봄 (3월 결산 vs 12월 결산, 연결 vs 별도, 금융형 vs 일반형) | 같은 계산 규칙, 같은 가격 기준일. 기간·기준·형식이 다르면 값마다 라벨 + "기준이 다르다"는 고정 문구 |
| 한쪽만 값이 있음(적자·외화 재무) | 없는 쪽은 사유. 한쪽 값만으로 비교처럼 보이지 않게 |
| 높고 낮음을 좋고 나쁨으로 읽음 | 정적 해석 참고: "업종·성장 기대·일회성 이익·회계 기준에 따라 달라서 높고 낮음만으로 어느 회사가 낫다고 말할 수 없어요" |
| AI 비교 설명이 값을 해석 | `pair_compare`는 시장 평가를 입력·언급하지 않는다(결정 6 유지). 값은 코드 표시에만 |

### 11.4 여전히 하지 않는 것과 이유

| 하지 않음 | 이유 |
|---|---|
| 기업 상세 경쟁사 섹션에 경쟁사들의 PER·PBR 표 | 3~5개 값이 모이면 사실상 업종 분포가 되고, 서비스가 고른 집합에서 "가장 싼 곳"을 보여 주는 표가 된다. 업종 평균 대비(D-49)와 같은 효과다. 목록의 비교 링크로 두 기업씩 볼 수 있다 |
| 세 기업 이상 비교 페이지 | 같은 이유. 현재 설계에도 없다(architecture.md §6.1은 두 기업) |
| 두 값의 차이·비율 계산, "상대 PER" | 서비스가 관계를 판정한다 |
| AI가 두 기업의 PER·PBR을 설명 | D-65 결정 6. 판정 규칙 없는 곳의 AI 설명은 AI가 판정하게 된다 |
