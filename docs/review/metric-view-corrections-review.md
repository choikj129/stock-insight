# 재무 지표 보기 보정(§9.7) 검토 — 4단계 화면 구현 전 설계 검토 자료

작성일: 2026-09-27 · 성격: **설계 검토 자료(결정 전).** 코드·테스트·fixture·프롬프트·검증기·화면은 바꾸지 않았다. 새 D-결정도 아직 만들지 않았다. 사용자가 검토한 뒤 결정한다.

## 0. 목적과 결론 요약

- **목적**: 4단계 화면을 만들기 전에 재무 지표를 사용자에게 **무엇으로, 어떤 뜻으로** 보여 줄지 아직 정하지 않은 것을 정리한다. work/4-financial-metrics-expansion.md §9.7 8)의 보정 7건을 현재 설계·코드와 대조했다.
- **범위 밖**: 클래스·API·DB 구조·컴포넌트·프론트엔드 방식. 이 문서는 화면이 전달해야 할 **의미**만 다룬다. 배치·색·모양은 화면 설계의 몫이다.
- **근거 문서**: [status.md](../status.md) §9·§7.4.33~§7.4.35, [decisions/README.md](../decisions/README.md) D-15·D-33·D-35·D-47~D-50·D-54~D-59, [spec/](../README.md) §3.1~§3.9·§4.4, [architecture.md](../architecture.md) §6, [product.md](../product.md) §4·§10·§11, [fx-v13 사람 검토 자료](fx-v13-d58-d59-human-review.md). 코드 사실은 `src/main`에서 직접 확인했다.

**결론**
- 새 D-결정이 필요한 것은 **두 가지**다.
  - **후보 A**: 지표 보기에서 규칙 판정을 어떻게 표시하는가. 신호를 어느 지표에 잇는지, 판정 자리의 상태, 사유를 둘 자리를 정한다.
  - **후보 B**: 지표마다 무엇과 비교하고 변화를 어떻게 말하는가. 화면과 AI 설명이 같은 값을 같은 뜻으로 보이게 하는 것도 포함한다.
- 나머지 보정은 기존 결정의 적용·문서 정정으로 충분하거나(D-47·D-49·product.md §10), 뒤 단계(단계 B·C, 동종업계)의 일이다.
- 지금 결정해야 하는 이유: 4단계 화면이 사용자에게 처음 나가는 재무 화면이다. 지표 목록은 화면·신호·AI가 함께 쓰는 기준이라 구현 뒤에 고치면 세 곳을 같이 고쳐야 한다(§9.7 7)).

## 1. 현재 상태

| 대상 | 상태 [확인] |
|---|---|
| 화면 | 없다. 템플릿이 아직 하나도 없다(`src/main/resources`에 `templates` 없음). 지표 보기는 설계만 있다(spec/signals-financial.md §3.9, D-47) |
| 재무 요약·신호 | 구현됨(3-3). 변화 신호 4종·상태 신호 2종·데이터 한계 신호 |
| ROE·유동비율·현금흐름 | 설계만(D-47·D-48). 단계 A·B |
| 재무 쉬운 설명 | fx-v13까지 구현·사람 검토 완료(§7.4.35). 게시 꺼짐. 앞머리 배지는 `[이름]` 표기이고 화면 칩은 미구현(D-58) |

화면에서 재무를 말하는 곳은 네 군데다. 역할 구분은 §9.7 1)에서 이미 일관적이라고 확인했다.

| 표면 | 답하는 질문 | 만드는 곳 |
|---|---|---|
| 요약 재무제표 | 숫자의 근거(원천 값) | 코드 |
| 지표 보기 | 지표 값과 비교 기준 대비 달라진 정도 | 코드 + 정적 문구 |
| 신호(배지·타임라인·리스크) | 규칙상 큰 변화인가, 방향·심각도 | 코드 |
| 재무 쉬운 설명 | 코드가 고른 변화가 함께·어떤 순서로 나타났나 | AI(코드가 준 사실·관계만) |

문제는 역할이 아니라 **같은 값이 여러 표면에 나올 때 뜻이 어긋날 수 있는 자리**다. 아래 항목 대부분이 여기에 해당한다.

## 2. 항목별 검토

§9.7 8)의 번호(#1~#7)와 새로 찾은 항목(N)을 함께 적는다. 각 항목의 결론은 끝의 "지금 결정?"에 있다.

### M1. 신호 배지를 어느 지표에 붙이는가 — 근거 지표 vs 확인 지표 (§9.7 1)(a), #3)

1. **현재 상태**
   - 설계 §3.9: "이 지표를 **확인 지표**로 가진 활성 신호가 있으면 배지". D-47은 이 자리를 "규칙상 큰 변화로 판정되었는지 여부"라고 적었다.
   - 확인 지표의 정의는 "이 신호가 있을 때 **앞으로 지켜볼** 지표"다(§3.1).
   - 코드에는 신호와 지표를 잇는 대응이 **세 벌** 있다.
     - 신호의 확인 지표(`watch_metrics`). 예: 흑자·적자 전환 → 영업이익·영업이익률.
     - AI 입력의 신호 → 사실(`SIGNAL_FACT_KEYS`). 예: 전환 → 영업이익·전환 사실.
     - D-58이 더한 검증기의 신호 → 지표 묶음(`SIGNAL_METRIC_FAMILY`). 예: 전환 → 영업이익·전년 영업이익·전환 사실.
   - §9.7 작성 때는 두 벌이었다. D-58로 한 벌이 늘었다.
2. **왜 결정이 필요한가**
   - "무엇이 변했나"와 "무엇을 지켜볼까"는 다른 질문이다.
   - 재무 신호에서는 두 뜻이 대체로 겹쳐 지금은 드러나지 않는다. 그러나 확인 지표 기준을 그대로 쓰면 어긋난다.
     - 흑자·적자 전환 배지가 영업이익률 지표 보기에도 붙는다. 영업이익률은 판정 대상이 아니었다(전환이 성립하면 영업이익률 변화 신호는 만들지 않는다, §3.7).
     - 공시 신호가 들어오면 더 커진다. 공급계약 체결의 확인 지표는 매출 증가율이다. 그러면 매출이 변하지 않았는데도 매출 지표 보기에 "규칙상 큰 변화" 배지가 붙는다.
3. **화면 혼란**: 사용자는 배지를 "이 숫자가 크게 변했다"로 읽는다. 변하지 않은 지표에 배지가 붙으면 숫자와 배지가 서로 다른 말을 한다.
4. **선택지**
   - (a) 지표 보기의 배지는 **근거 지표**(그 신호를 만든 값)에만 붙인다. 확인 지표는 "앞으로 지켜볼 점"에만 쓴다. §9.7의 권고다.
   - (b) 확인 지표 기준을 유지하고, 배지 문구를 "지켜볼 신호"로 바꾼다. 지표 보기의 "큰 변화 여부" 자리의 뜻이 달라진다.
   - (c) 둘 다 표시하고 구분한다. 한 지표 보기에 신호 표시가 두 종류가 되어 복잡하다.
5. **기존 설계와의 관계**
   - D-58이 AI 설명에서 이미 (a)의 원칙을 정했다. 배지는 **자기 지표의 사실** 앞에만 온다.
   - 화면이 (b)를 쓰면 같은 신호가 AI 설명에서는 A 지표에, 화면에서는 B 지표에 붙는다.
   - (a)는 D-58을 화면으로 넓히는 것이다.
6. **지금 결정?** **예(후보 A).** 대응을 어떤 구조로 합칠지는 구현 판단이라 정하지 않는다. "지표 보기의 배지는 무엇을 뜻하는가"만 정한다.

### M2. 판정 자리의 상태가 둘뿐이다 (§9.7 3), #2)

1. **현재 상태**
   - §3.9의 "큰 변화 여부" 자리는 배지 또는 "규칙상 큰 변화로 표시되지 않음" 두 가지뿐이다.
2. **왜 결정이 필요한가**: 실제 상태는 넷이다.
   1. 신호 있음(배지).
   2. 판정했고, 큰 변화가 아님.
   3. 이 기업은 판정 대상이 아님(금융형·비원화·기준값 미만·재무상태표 불일치).
   4. 이 지표에는 판정 규칙이 없음(ROE·유동비율·당기순이익·기말 현금, 엇갈림 신호를 켜기 전의 현금흐름).
   - 3과 4에서 "규칙상 큰 변화로 표시되지 않음"은 사실이 아니다. 판정하지 않았는데 판정한 것처럼 읽힌다.
3. **화면 혼란 — 골든셋 실례 (fx-v13 관찰 3과 연결)**
   - 1640(프레스티지바이오파마)은 비원화(미국 달러)다. 그래서 매출 증감·영업이익률 변화 신호의 판정 대상이 아니다(§3.7: 비원화 제외).
   - 영업이익률은 전년보다 111.1%p 높아졌다. 영업이익률 변화 신호의 문턱(±10%p)의 열 배가 넘는다.
   - 지금 설계대로면 이 지표 보기에 "규칙상 큰 변화로 표시되지 않음"이 붙는다. 사용자는 "111%p 변화가 규칙상 작은 변화로 판정됐다"로 읽는다.
   - AI 설명도 같은 자리에서 같은 오해를 준다. 개요의 고정 문구 "규칙상 큰 변화로 표시된 항목이 없어요" 바로 뒤에 "영업이익률은 … 111.1%p 높아졌어요"가 온다.
   - fx-v13 사람 검토는 이 자리를 "배치가 첫인상을 좌우"하는 문제로 봤다(관찰 3). 원인의 일부는 배치가 아니라 **판정 상태 표현**이다.
4. **선택지**
   - (a) 네 상태를 나눠 표시한다. 3은 "판정 대상 아님"과 사유, 4는 "판정 규칙 없음"이다.
   - (b) 3·4를 "판정하지 않음" 하나로 묶는다. 사용자에게는 둘의 차이가 작다. 다만 3은 기업 사정이고 4는 지표의 성격이라, 사유 문구가 달라야 한다.
   - (c) 2만 따로 표시하고, 3·4는 아무것도 표시하지 않는다. 빈자리가 "큰 변화 아님"으로 읽힐 위험이 남는다. "빈칸으로 두지 않는다"는 §3.9 원칙과도 부딪힌다.
5. **기존 설계와의 관계**
   - D-15·D-47: 좋고 나쁨의 방향은 신호에만 있다. 판정 상태를 정확히 말하는 것은 이 원칙 안이다.
   - §3.9 "추정하거나 빈칸으로 두지 않고 사유를 보여 준다"를 판정 자리까지 적용하는 것이다.
   - AI 설명의 NONE 고정 문구(D-54·D-57)도 기업 단위에서 같은 문제를 가진다. 이 문구를 바꾸려면 프롬프트 버전을 올려야 한다. 지금 바꾸지 않고, 화면에 AI 설명을 붙일 때 이 결정에 맞춰 다시 본다(§6의 "화면 구현 단계").
6. **지금 결정?** **예(후보 A).** 네 상태의 구분과 그 뜻을 정한다. 문구는 정적 콘텐츠 검토에서 정한다.

### M3. 사유가 지표 단위 하나뿐이다 + 이름 없는 사유 (§9.7 3), #2·#7)

1. **현재 상태**
   - 지표 보기의 사유 자리는 "계산하지 않음" 하나다.
   - 유동부채 ≤ 0과 ROE 비교 기간 없음은 사유 이름이 없다.
2. **왜 결정이 필요한가**: 부분마다 사정이 다르다.
   - 값은 있는데 비교가 없다: ROE의 전전기말 자본 없음, 12개월이 아닌 회계연도, 4분기 파생값, 기준 공백.
   - 값·비교는 있는데 증가율만 없다: 기준값 미만(`SMALL_BASE`).
   - 값·비교는 있는데 판정 대상이 아니다: 비원화·금융형의 매출 신호. 이것이 M2의 상태 3이다.
3. **화면 혼란**
   - 지표 하나에 "계산하지 않음"이 붙으면 값까지 없는 것으로 읽힌다.
   - 반대로 값만 보이고 비교가 없으면 이유를 알 수 없다.
4. **선택지**
   - (a) 사유를 **값·비교·판정** 세 자리에 따로 둔다(§9.7 권고).
   - (b) 지표 단위 한 자리를 유지하되, 여러 사유를 나열한다. 어느 부분의 사유인지가 흐려진다.
5. **기존 설계와의 관계**
   - 사유 코드는 이미 충분하다(§3.6, §3.8 플래그). 새 판단이 아니라 표시 자리를 나누는 일이다.
   - 이름 없는 사유 두 개는 단계 A에서 지표를 만들 때 이름을 붙이면 된다. 결정이 필요한 문제가 아니다.
6. **지금 결정?**
   - 세 자리 구분: **예(후보 A에 포함).** M2와 같은 자리의 문제다.
   - 이름 붙이기: 아니오. 단계 A 구현 때 한다.

### M4. 지표마다 비교 방식과 변화 표현이 다르다 (§9.7 2), #1)

1. **현재 상태**
   - §3.9의 "비교"는 모든 지표에 한 틀을 쓴다: 변화량 + 산술 방향(늘었다·줄었다·같다) + 이어진 기간 수.
   - §3.6은 지표마다 비교 방식을 따로 정해 두었다.
   - §9.7 2)가 지표별 권고 표를 만들었지만 결정문에는 없다.
2. **왜 결정이 필요한가**: 한 틀을 그대로 쓰면 오해가 생기는 조합이 있다.
   - **부호가 바뀌거나 둘 다 음수인 값**(영업이익·순이익·현금흐름)
     - 예: 2715의 영업이익 "−28.4억원 → −4.5억원, 늘었다".
     - D-55는 AI에게 이 서술(적자끼리의 크기 변화)을 막았고, 영업이익의 "늘었다"는 둘 다 흑자일 때만 준다(R2).
     - 화면이 한 틀을 쓰면, AI가 쓰지 못하는 말이 화면에는 나간다.
   - **변화량의 부호와 방향어가 겹친다**
     - D-58은 AI 문장 안의 변화량에서 부호를 뺐다. "-69.3% 줄었어요"는 겹말이다.
     - §3.9의 틀(변화량 + 산술 방향)은 그대로 쓰면 "−69.3% 줄었다"가 된다.
     - 그러면 같은 사실(737 매출)이 AI 설명에서는 "69.3% 줄었어요", 지표 보기에서는 "−69.3% 줄었다"로 보인다.
   - **이름에 방향이 들어가면 부호와 충돌한다**
     - D-59는 AI 입력의 사실 이름에 방향을 넣었다(매출 감소율, 부채비율 상승폭).
     - 화면이 "매출 증가율 −69.3%"로 쓰면 이름·부호·방향어가 제각각이 될 수 있다.
   - **자본잠식의 수준 차이가 드러나지 않는다 (fx-v13 관찰 4와 연결)**
     - 908은 자본총계가 음수(−1,477.8억원), 1640·716은 양수이지만 자본금보다 적다.
     - AI 문장은 둘 다 "자본금보다 적어요"다.
     - 지표 보기의 잠식률은 908에서 약 290%다((775.5 + 1,477.8) ÷ 775.5). "잠식률 290%"는 뜻을 알기 어렵다.
     - 신호 카탈로그는 이미 "자본잠식 (부분·완전)"으로 둘을 나눠 적었고, 심각도도 완전잠식을 높음으로 둔다(§3.4·§3.7). 그런데 화면·AI 어디에도 부분/완전이 사실로 나오지 않는다.
3. **화면 혼란**
   - 적자가 줄어든 것을 "영업이익 늘었다"로 보면 흑자가 난 것으로 오해할 수 있다.
   - 부호와 방향어가 겹치면 "두 번 줄었다"처럼 읽힌다.
   - 같은 숫자가 화면과 AI 설명에서 다르게 보이면 어느 쪽이 맞는지 의심하게 된다.
4. **선택지**
   - 지표별 비교 유형(비교 기준·변화 표현·방향어 조건·이어진 기간 수)
     - (a) §9.7 2)의 권고 표를 그대로 결정으로 올린다.
     - (b) 권고 표를 올리되 현금흐름·기말 현금 행은 단계 B 결정으로 미룬다. 화면 첫 출시에 현금흐름이 없다.
   - 변화량 표현
     - (a) 부호 없는 크기 + 방향어("69.3% 줄었어요"). D-58의 AI 표현과 같다.
     - (b) 부호 있는 숫자만, 방향어 없음("−69.3%").
     - (c) 둘 다. 겹말이라 권하지 않는다.
   - 자본잠식
     - (a) 부분/완전을 코드 사실로 표시한다. 자본잠식은 D-47이 이미 "부호로 정해지는 사실"로 분류했다.
     - (b) 잠식률만 표시한다. 완전잠식에서 값의 뜻이 약하다.
5. **기존 설계와의 관계**
   - D-33·D-35(같은 보고서 비교, 영업이익 증가율 없음), D-47(산술 방향, 부호 사실)을 지표별로 구체화한다.
   - D-55 R2·D-58 결정 5와 같은 경계를 화면에도 쓴다.
   - 자본잠식 부분/완전을 사실로 두면 fx-v13 관찰 4의 화면 쪽 답이 된다. AI 문형(D-55 R6)은 바꾸지 않는다. 바꾸려면 입력·프롬프트 버전을 올려야 하고, 사람 검토 판단대로 이번 범위 밖이다.
6. **지금 결정?** **예(후보 B).**
   - 매출·영업이익·순이익·영업이익률·ROE·부채비율·유동비율·자본잠식 행은 지금 정한다.
   - 현금흐름·기말 현금 행은 방향만 적고 단계 B에서 확정해도 된다.

### M5. 기간 라벨과 비교 기준 시점이 화면·AI·문서에서 다르다 (§9.7 2)·6), #1 + 새로 찾음)

1. **현재 상태**
   - **기간 라벨 규칙이 두 벌이다.** [확인]
     - spec/signals-financial.md §3.6(화면·재무 요약의 기준): 비12월 결산은 "2026.06 · 1분기(2026.04~2027.03 회계연도)"처럼 회계연도 분기 번호를 쓴다.
     - D-59(AI 설명, 구현됨): 회계연도 분기 번호를 빼고 달로만 쓴다("2026년 4~6월"). 12개월이 아닌 회계연도는 실제 기간("2025.11~12 회계연도")이다.
     - D-59의 근거는 fx-v12 사람 검토였다. "2026.01~03(3분기)"가 흔히 쓰는 "3분기 = 7~9월"과 부딪힌다.
     - §3.6의 예시는 이 결정 전 표기 그대로 남아 있다.
   - **비교 기준 시점을 표시하는 규칙이 없다.**
     - §9.7 6)이 "비교 기준 시점의 표시는 정해져 있지 않다"고 짚었다.
     - AI 설명은 D-56으로 "지난 회계연도 말", "전년 같은 분기"를 쓴다.
     - §9.7 2)는 화면에 날짜를 붙이라고 권했다("2025년 12월 말보다"). 날짜 없는 "전기말"은 쓰지 않는다.
   - **잔액 지표의 기준점이 서로 다르다.**
     - 기말 현금은 전년 같은 기간 말과 비교한다.
     - 부채비율·유동비율은 직전 사업연도 말과 비교한다.
   - **한 묶음 안에 기간이 섞인다.** 최신이 분기인 기업의 수익성 묶음에는 "영업이익률 2026년 2분기"와 "ROE 2025년"이 함께 놓인다.
2. **왜 결정이 필요한가**
   - 같은 기간이 화면에서는 "1분기", AI 설명에서는 "4~6월"로 보이면 사용자는 다른 기간으로 읽는다. 3월·6월 결산 기업(608·810·1640)에서 실제로 생긴다.
   - 기준점을 날짜 없이 쓰면 "무엇과 비교했나"를 알 수 없다. 특히 분기 보고서의 재무상태 비교 기준이 직전 분기가 아니라 직전 사업연도 말이라는 점이 드러나지 않는다.
3. **화면 혼란**
   - 608(6월 결산): §3.6 규칙대로면 화면은 "2026.03 · 3분기(2025.07~2026.06 회계연도)", AI 설명은 "2026년 1~3월"이다. "3분기"는 흔히 7~9월로 읽혀, 사용자는 두 기간이 같은지 판단할 수 없다.
   - 부채비율 "+5.6%p"만 보면 직전 분기 대비로 읽기 쉽다. 실제 기준은 직전 사업연도 말이다.
4. **선택지**
   - 기간 라벨
     - (a) 화면·재무 요약·AI 설명이 **한 가지 라벨 규칙**을 쓴다. D-59의 규칙을 기준으로 하고 §3.6 예시를 고친다.
     - (b) 화면은 회계연도 분기를 쓰고 AI만 달로 쓴다. 지금 상태이며, 위의 혼란이 남는다.
   - 비교 기준
     - (a) 모든 비교에 기준 시점을 날짜로 붙인다.
     - (b) 기준의 종류만 쓴다("전년 같은 분기", "지난 회계연도 말").
     - (c) 둘 다 쓴다(종류 + 날짜).
     - AI 설명은 이미 (b)다. 화면이 (a)나 (c)를 쓰면 AI 설명 옆에서 기준을 확인하는 자리가 된다.
   - 섞인 기간: 값마다 자기 기간 라벨을 붙인다. 묶음 제목에는 기간을 두지 않는다.
5. **기존 설계와의 관계**
   - D-59가 AI 쪽에서 이미 답을 냈다. 화면으로 넓히는 것이다.
   - D-41·D-56은 "표시는 렌더링할 때 코드가 만든다"를 정했다. 라벨도 같다.
   - D-33(같은 보고서 비교)이 기준점의 뜻을 정했다. 이것은 그 뜻을 **보이게** 하는 일이다.
6. **지금 결정?** **예(후보 B에 포함).** 라벨 규칙이 두 벌인 것은 결정 없이 두면 화면 구현 때 옛 규칙(§3.6)을 따라가게 된다.

### M6. "이어진 기간 수" — 정의가 흩어져 있고, 신호 지속 값이 비어 있다 (§9.7 1)(d)·2), #3)

1. **현재 상태** [확인: 코드]
   - 설계(§3.1·§3.7)는 변화 신호에도 지속(같은 방향이 이어진 기간 수)을 계산한다고 적었다.
   - 구현은 변화 신호 4종(매출·영업이익률·전환·부채비율)의 지속을 비워 둔다(`FinancialSignalCalculator`가 `null`을 넘긴다). 상태 신호 2종(영업적자 지속·자본잠식)만 채운다.
   - AI 입력은 매출 연속 흐름을 따로 센다(`revenue_yoy_run`). 영업적자 연속(`operating_loss_run`)은 영업적자 지속 신호의 값을 쓴다.
   - 지표 보기(§3.9)가 또 세면 세 번째 계산이 된다.
2. **왜 결정이 필요한가**
   - 화면·신호·AI의 "몇 분기째"가 서로 다를 수 있다.
   - 뜻이 없는 지표가 있다. 부채비율·유동비율은 분기마다 같은 기준점(직전 사업연도 말)과 비교해 같은 변화를 여러 번 센다. 현금흐름은 누적 기간이 겹친다(§9.7 2)).
3. **화면 혼란**
   - AI 설명 "매출 감소가 2분기째 이어지고 있어요" 옆 지표 보기에 "3분기 연속 감소"가 나오면 어느 쪽도 믿기 어렵다.
   - 부채비율 "3분기 연속 상승"은 같은 연초 기준과의 비교를 세 번 센 것이라 실제 흐름이 아니다.
4. **선택지**
   - 표시 대상
     - (a) 뜻이 있는 지표에만 둔다(§9.7 2) 표: 매출·영업이익률은 분기끼리·연간끼리, 영업이익은 흑자·적자 상태의 연속, 자본잠식은 상태의 연속. 부채비율·유동비율·ROE·현금흐름은 없음).
     - (b) 화면 첫 출시에는 신호가 가진 연속(영업적자 지속·자본잠식)만 보여 준다.
   - 정의
     - 어느 선택이든 화면·신호·AI가 **같은 정의·같은 값**을 쓴다는 원칙은 정해야 한다.
     - 신호의 지속 값을 설계에 맞춰 채울지, 설계를 구현에 맞춰 고칠지도 정해야 한다. 이것은 3-3의 설계-구현 불일치다.
5. **기존 설계와의 관계**
   - §3.7의 지속 정의(부호 기준, 문턱값 아님)가 기준이 된다.
   - D-45(흐름 사실의 뜻)·D-56(흐름 사실은 분기 기준)이 AI 쪽 정의다.
   - 1640처럼 최신이 사업보고서인 기업에서 "분기로 세면"이 필요했던 것(fx-v13 관찰 2)은 이 값이 **분기 기준**이라서다. 화면에도 단위(분기)를 붙이는 규칙이 필요하다.
6. **지금 결정?** **예(후보 B에 포함).**
   - 표시 대상과 "한 정의" 원칙을 정한다.
   - 신호 지속 값의 불일치를 설계와 구현 중 어느 쪽에 맞출지도 이 결정에서 방향을 정한다. 실제 수정은 단계 A 구현 때 한다.

### M7. 같은 값이 여러 번 나오고, 표면마다 표현이 다를 수 있다 (§9.7 1)(c)·(e))

1. **현재 상태**
   - 요약 재무제표 13행 가운데 9행이 지표 보기의 현재 값과 같다. 추이 차트까지 치면 세 번 보인다.
   - AI 설명도 그 가운데 일부를 문장으로 다시 말한다(D-54가 배정한 사실만).
   - D-47은 "화면과 AI가 같은 구조를 쓴다", §3.9는 "AI는 관여하지 않는다"라고 적었다. 경계 문구가 어긋난다.
2. **왜 결정이 필요한가**
   - 값 자체는 어긋나지 않는다. 모두 같은 재무 요약에서 나온다. AI 설명의 값 스냅샷은 정정·재계산 때 무효화된다(D-40·D-42). 
   - 어긋날 수 있는 것은 **표현**이다: 부호(M4), 방향어(M4), 기간 라벨(M5), 기준 시점(M5), 배지(M1), 연속 수(M6).
3. **화면 혼란**: 같은 매출이 요약 재무제표·지표 보기·AI 설명에서 셋 다 다른 모양으로 나온다.
4. **선택지**
   - (a) 원칙 하나만 정한다: **한 값은 모든 표면에서 같은 표시·같은 기간 라벨·같은 비교 기준으로 보인다.** 요약 재무제표는 근거 표(값과 비교 열만, 방향·배지·해석 없음)로 둔다.
   - (b) 표면마다 따로 정한다. 지금 상태이며 M4~M6의 어긋남이 그대로 남는다.
5. **기존 설계와의 관계**
   - D-41·D-56·D-58·D-59가 AI 쪽 표시 규칙을 이미 정했다. (a)는 그것을 화면의 기준으로 삼는 것이다.
   - AI와 지표 보기의 경계는 D-54·D-55로 실제로는 이미 정해졌다. AI는 배정된 사실과 코드가 준 관계만 쓰고, 지표 정의를 쓰지 않는다. D-47의 문구만 고치면 된다. **새 결정은 필요 없다.**
6. **지금 결정?**
   - "한 값, 한 표시" 원칙: **예(후보 B에 포함).**
   - D-47 경계 문구 정정: 결정 불필요, 문서 정정만.
   - 화면에서 무엇을 어디에 둘지: 화면 설계의 일.

### M8. 유동비율 단위 (§9.7 2), #7)

1. **현재 상태**: D-47·§9.1은 "중앙값 1.67배", §3.6은 "(%)"와 "%p"다.
2. **왜 결정이 필요한가**: 같은 안정성 묶음의 부채비율이 %다. 단위가 다르면 나란히 읽기 어렵다.
3. **선택지**
   - (a) %·%p로 통일한다(§9.7 권고, §3.6과 같다).
   - (b) 배로 쓴다. 비교가 "0.2배 늘었다"가 되어 %p보다 어색하다.
4. **기존 설계와의 관계**: §3.6이 이미 %다. D-47의 서술("1.67배")은 분포 설명이다.
5. **지금 결정?** 작은 문제라 후보 B에 한 줄로 넣는다. §3.6이 이미 %라 사실상 문서 정정이다.

### M9. "불확실" 방향을 표시할 길이 없다 (§9.7 3), #7)

1. **현재 상태** [확인: 코드]
   - 방향은 긍정·부정·불확실 셋이다(§3.1).
   - 배지 이름 표(`StaticContent.badgeName`)는 긍정이 아니면 모두 부정 표를 쓴다.
2. **왜 결정이 필요한가**
   - 지금 활성인 재무 신호에는 불확실 방향이 없다. 데이터 한계 신호는 배지가 아니라 한계 문구로 나간다.
   - 불확실 배지가 필요해지는 때는 두 경우다. 엇갈림 신호를 켤 때(단계 B), 그리고 공시 신호(대규모 시설투자·유상증자 등)가 들어올 때다.
3. **화면 혼란**: 불확실 신호가 부정 배지로 보이면 "나쁜 일"로 읽힌다.
4. **선택지**: 원칙은 이미 있다(§3.1: 불확실은 좋고 나쁨을 말하지 않는다). 모양은 화면 설계다.
5. **기존 설계와의 관계**: D-15·§3.1로 뜻은 정해져 있다. 구현 결함이다.
6. **지금 결정?** 아니오. 새 결정도 필요 없다. 단계 B 전(또는 공시 신호 구현 전)에 코드를 고친다.

### M10. 정적 문구가 수준 판정을 되살릴 수 있다 (§9.7 4), #4)

1. **현재 상태**
   - 수준 판정·종합 점수는 금지다(D-47, product.md §10).
   - §9.5의 정적 문구 검토 체크리스트는 평가어만 막는다.
2. **왜 결정이 필요한가**
   - "유동비율 200% 이상이면 안정" 같은 교과서식 기준이 해석 참고에 들어가면, 코드가 막은 판정이 문구로 되살아난다.
   - ROE는 자본이 작을수록 크게 나온다(절댓값 100% 초과 50벌 중 23벌이 잠식 기업).
3. **선택지**
   - 체크리스트에 **숫자 기준·구간·"보통 ~ 이상" 금지**를 더한다.
   - ROE 해석 참고에 "자본이 작으면 비율이 크게 나온다"는 조건부 사실 문구를 둔다. 자본잠식 기업에 코드가 고른다. §9.7의 선택 권고다.
4. **기존 설계와의 관계**: D-47 "수준 판정 없음"의 적용이다. 새 판단이 없다.
5. **지금 결정?**
   - 새 D-결정은 필요 없다. 체크리스트 한 줄은 단계 A의 정적 문구 초안을 쓰기 전에 문서에 더한다.
   - ROE 조건부 문구는 화면 구현 단계에서 정한다.

### M11. 순위·백분위·업종 내 위치 (§9.7 5), #5)

1. **현재 상태**
   - 동종업계 참고 값은 이번 확장에서 하지 않는다(§9.4).
   - D-47은 업계 참고 값에 "순위·평가어는 붙이지 않는다"고 적었다.
2. **왜 결정이 필요한가**
   - 동종업계 정의를 구현한 뒤에도 순위를 만들지 않는다는 명시가 없다.
   - 다만 4단계 화면에는 동종업계 데이터가 없어 지금 생길 수 없다.
3. **기존 설계와의 관계**: product.md §10(종합 평가 없음)과 D-47로 뜻은 막혀 있다.
4. **지금 결정?** 아니오. 동종업계 정의 단계의 별도 결정으로 둔다. §9.4 "하지 않는 것"에 한 줄 적는 것은 문서 정정이다.

### M12. `cash_flow` 작성·검증 규칙과 D-55 (§9.7 6), #6)

- 단계 C(AI 설명 확장)의 일이다. 화면 지표 보기와는 별개다.
- 사람 검토 시점 조건은 풀렸지만, 단계 B(현금흐름 수집) 뒤라 급하지 않다(§7.4.35).
- **지금 결정?** 아니오.

### M13. PER·밸류에이션 (사용자 요청 점검)

1. **현재 상태**: D-49로 핵심 범위 밖이다. 시세 모듈을 들여도 신호·AI 입력·비교에 쓰지 않는다.
2. **화면 관련 점검**
   - 지표 보기에 PER 자리를 두고 "계산하지 않음"으로 채우면 안 된다. "계산하지 않음"은 "우리가 계산하는 지표인데 이번엔 못 했다"는 뜻이다(M3).
   - PER은 범위 밖이므로 자리 자체가 없다.
3. **지금 결정?** 아니오. D-49로 충분하다. 새 결정이 필요 없다.

- 값 자체가 어긋날 경로는 막혀 있다. 모두 같은 재무 요약에서 나오고, AI 스냅샷은 정정 때 무효화된다(D-40·D-42).
- 어긋남은 **표현 층**에 있다: 판정 상태(M2), 부호·방향어(M4), 기간·기준 라벨(M5), 연속 수(M6), 배지 연결(M1).

## 6. D-결정 후보

두 후보 모두 **무엇을 보여 주고 어떤 뜻을 전하는지**만 정한다. 구현 구조(대응을 어디에 둘지, 어떤 형태로 전달할지)는 정하지 않는다.

### 후보 A — 지표 보기에서 규칙 판정을 어떻게 표시하는가 (M1·M2·M3)

**결정해야 할 핵심 질문**
1. 지표 보기의 신호 배지는 "이 지표가 규칙상 크게 변했다"(근거 지표)를 뜻하는가, "이 신호가 있을 때 이 지표를 지켜보라"(확인 지표)를 뜻하는가?
2. 판정 자리는 몇 가지 상태를 구분해 보여 주는가? 판정하지 않은 지표를 판정한 것처럼 보이지 않게 하려면 무엇이 필요한가?
3. "계산하지 않음"의 사유는 지표 하나에 붙는가, 값·비교·판정 각 부분에 붙는가?

**권장 방향**
1. 배지는 **근거 지표**에만 붙인다. 확인 지표는 "앞으로 지켜볼 점"에만 쓴다. AI 설명(D-58)과 화면이 같은 신호를 같은 지표에 붙인다.
2. 판정 자리는 **네 상태**를 구분한다: 신호 있음 / 판정했고 큰 변화 아님 / 이 기업은 판정 대상 아님(사유) / 이 지표에는 판정 규칙 없음. "규칙상 큰 변화로 표시되지 않음"은 두 번째 상태에만 쓴다.
3. 사유는 **값·비교·판정** 세 자리에 따로 둔다. 기업 전체의 한계는 지금처럼 데이터 한계 신호 문구로 두고, 같은 원인이면 지표 자리에는 짧게만 쓴다(문구는 화면 설계).

**검토한 대안**: 확인 지표 기준 유지 + 배지 문구 변경. 지표 보기 "큰 변화 여부" 자리의 뜻이 바뀌고, AI 설명과 다른 지표를 가리킨다.

**관계**: D-15·D-47(방향은 신호에만)을 구체화한다. D-58의 배지 원칙을 화면으로 넓힌다. §3.1의 확인 지표 정의는 그대로 둔다. §3.9의 "확인 지표로 가진 신호" 문구를 고친다.

**재검토 조건(제안)**: 공시 신호를 구현할 때 근거 지표가 없는 신호(최대주주 변경 등)의 지표 보기 표시를 다시 본다.

### 후보 B — 지표마다 무엇과 비교하고 변화를 어떻게 말하는가, 그리고 화면과 AI 설명의 표시 일치 (M4·M5·M6·M7·M8)

**결정해야 할 핵심 질문**
1. 지표마다 비교 기준, 변화 표현, 산술 방향어("늘었다·줄었다")를 쓰는 조건, 이어진 기간 수를 보여 줄지를 어떻게 정하는가?
2. 부호가 바뀌거나 둘 다 음수인 값(영업이익·순이익)에 "늘었다·줄었다"를 쓰는가?
3. 변화량은 부호로 보이는가, 방향어로 보이는가? AI 설명과 같은 표기를 쓰는가?
4. 기간 라벨과 비교 기준 시점은 어떻게 표시하는가? 화면과 AI 설명이 같은 규칙을 쓰는가?
5. 이어진 기간 수는 한 정의를 공유하는가? 신호의 지속 값이 설계와 다른 것은 어느 쪽에 맞추는가?
6. 자본잠식은 부분/완전을 사실로 보여 주는가?
7. 유동비율 단위는 무엇인가?

**권장 방향**
1. §9.7 2)의 지표별 권고 표를 결정으로 올린다. 매출·영업이익·순이익·영업이익률·ROE·부채비율·유동비율·자본잠식 행을 지금 확정한다. 현금흐름·기말 현금 행은 방향만 두고 단계 B에서 확정한다.
2. 부호가 끼는 값(영업이익·순이익, 뒤의 현금흐름)은 **둘 다 양수일 때만** 방향어를 쓴다. 그 밖에는 두 값과 흑자·적자 상태(부호 사실)만 보인다. D-55 R2와 같은 경계다.
3. 문장·설명 자리의 변화량은 **부호 없는 크기 + 방향어**로 쓴다(D-58과 같다). 수준 값은 부호를 유지한다(음수 영업이익률은 값이다). 숫자만 늘어놓는 표 자리의 표기는 화면 설계에 맡기되, 한 자리에 부호와 방향어를 겹쳐 쓰지 않는다.
4. **한 값은 모든 표면에서 같은 표시·같은 기간 라벨·같은 비교 기준으로 보인다.**
   - 기간 라벨은 D-59의 규칙을 화면·재무 요약에도 쓴다(§3.6 예시를 고친다).
   - 비교에는 기준 시점을 붙인다(종류 + 날짜 권장: "지난 회계연도 말(2025년 12월 말)보다").
   - 한 묶음에서 기간이 섞이면 값마다 자기 기간 라벨을 붙인다.
   - 요약 재무제표는 근거 표(값과 비교 열만)로 둔다.
5. 이어진 기간 수는 **뜻이 있는 지표에만**(매출·영업이익률은 분기끼리·연간끼리, 영업이익 흑자·적자 상태, 자본잠식 상태) 보이고, 단위(분기·연도)를 붙인다. 화면·신호·AI가 **같은 정의·같은 값**을 쓴다. 신호 지속 값은 §3.7 설계(부호 기준)에 맞춘다. 설계를 바꾸면 D-45·D-56의 AI 흐름 사실 정의와도 다시 맞춰야 해서 비용이 더 크다.
6. 자본잠식은 **부분/완전을 코드 사실**로 보인다. 잠식률은 부분잠식에서만 보인다. 완전잠식에서 100%를 넘는 비율은 뜻을 전하기 어렵다. AI 문형(D-55 R6)은 바꾸지 않는다.
7. 유동비율은 %·%p로 쓴다(§3.6과 같다).

**검토한 대안**
- 모든 지표에 한 틀(§3.9 현재): 적자끼리의 "늘었다", 재무상태 연속 수의 중복 계산이 생긴다.
- 화면은 부호 숫자, AI는 방향어로 따로: 같은 사실이 두 모양이 된다. D-58이 없애려던 겹말이 화면에 남는다.
- 비교 기준을 날짜만 표시: AI 설명의 "지난 회계연도 말"과 대응을 사용자가 스스로 맞춰야 한다.

**관계**: D-33·D-35·D-47을 지표별로 구체화한다. D-41·D-56·D-58·D-59의 표시 규칙을 화면에 적용한다. D-55 R2의 방향 경계를 화면에 적용한다. D-47의 "화면과 AI가 같은 구조를 쓴다"를 "같은 값·같은 표시를 쓴다, AI는 배정된 사실만"으로 정정한다.

**범위 밖**: 화면 배치(변화 중심 배치의 구체), 색·아이콘, 차트, 정적 문구의 문장, 현금흐름 행의 확정(단계 B), 동종업계 참고 값.

## 7. 최종 분류

### 지금 결정할 사항 (4단계 화면·단계 A 전)
- **후보 A**: 배지는 근거 지표에(M1), 판정 자리 네 상태(M2), 사유는 값·비교·판정 자리별로(M3).
- **후보 B**
  - 지표별 비교 유형 표(M4, 현금흐름 행 제외).
  - 부호가 끼는 값의 방향어 조건(M4).
  - 변화량 표현을 AI 설명과 일치(M4).
  - 기간 라벨·비교 기준 시점 한 규칙(M5).
  - 이어진 기간 수의 표시 대상·한 정의·신호 지속 값의 기준(M6).
  - "한 값, 한 표시"(M7).
  - 자본잠식 부분/완전(M4).
  - 유동비율 단위(M8).

### 화면 구현 단계에서 결정할 사항
- 네 판정 상태·사유·배지 칩(D-58 결정 1)의 모양과 문구. 같은 원인을 데이터 한계 문구와 지표 사유에서 두 번 말하지 않는 표시 규칙(M2·M3·M9).
- 변화 중심 배치: 신호가 있는 지표를 앞에 두는 방식, 요약 재무제표·추이 차트의 자리(M7).
- 숫자만 늘어놓는 표 자리의 부호 표기(후보 B 3의 범위 안에서).
- ROE 조건부 해석 참고 문구(자본이 작으면 비율이 크게 나온다)(M10).
- 재무 쉬운 설명을 화면에 붙일 때
  - AI 개요의 NONE 고정 문구가 판정 대상이 아닌 변화(1640)와 함께 놓이는 문제(M2, fx-v13 관찰 3). 문구를 바꾸면 프롬프트 버전이 오른다.
  - 개요와 지표 보기 사이의 시각적 구분.
- 정적 문구 초안(정의·해석 참고·사유)과 사람 검토.

### 이후 관찰할 사항
- 820 규칙 14 반복, 1640 "분기로 세면"(fx-v13 관찰 1·2, 다음 재검증).
- 화면에서 자본잠식 부분/완전을 보인 뒤에도 AI 문형("자본금보다 적어요")이 부족하다고 확인되는지(fx-v13 관찰 4).
- 1640형(판정 대상이 아닌 기업)에서 화면 네 상태와 AI 설명이 함께 놓였을 때 사람이 어떻게 읽는지(관찰 3).
- ROE가 다른 서비스 값과 달라 혼란이 생기는지(D-47 재검토 조건, 지배주주 기준).
- 공시 신호를 구현할 때 근거 지표가 없는 신호와 불확실 방향 배지(M1·M9).

### 현재는 변경할 필요가 없는 사항
- **네 표면의 역할 구분**(§9.7 1)): 일관적이다.
- **PER·밸류에이션**(M13): D-49로 충분하다. 지표 보기에 자리를 두지 않는다.
- **수준 판정·종합 점수 금지**(M10): D-47·product.md §10으로 충분하다. 체크리스트에 숫자 기준 금지 한 줄만 문서로 더한다.
- **순위·백분위**(M11): 4단계에 데이터가 없다. 동종업계 정의 단계에서 따로 정한다(§9.4 "하지 않는 것"에 한 줄 적는 문서 정정은 가능).
- **AI와 지표 보기의 경계**(M7의 (e)): D-54·D-55로 실제 경계는 정해졌다. D-47 문구만 정정한다.
- **불확실 방향 배지**(M9): 뜻은 §3.1로 정해졌다. 단계 B 또는 공시 신호 전에 고칠 구현 결함이다.
- **이름 없는 사유 코드 두 개**(M3): 단계 A 구현 때 이름을 붙인다.
- **`cash_flow` 작성·검증 규칙**(M12): 단계 C에서 D-55 계약으로 다시 정한다.
- **AI 설명의 입력·프롬프트·검증기**: 이번 검토로 바꿀 것이 없다. 화면 쪽 결정이 AI 쪽 규칙을 따라오는 방향이다.
