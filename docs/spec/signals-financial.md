# 기업 신호·재무 지표 명세

> 코드가 판정하는 규칙: 기업 신호(§3~§3.4), 재무 지표·재무 신호·지표 보기(§3.5~§3.9), 향후 이벤트·잠정실적·거래 상태(§3.10~§3.12).

## 3. 기업 신호

기업 신호는 코드가 규칙으로 판정한 사실이다. 리스크 섹션과 향후 전망의 판단 근거는 모두 기업 신호에서 나온다. 저장 위치는 `company_signal` 테이블이다.

### 3.1 필드

| 필드 | 설명 |
|---|---|
| 유형 | 규칙 카탈로그의 신호 유형 코드 |
| 근거 키 | 신호를 만든 원천의 식별자 (재무 기간, 공시번호 등). **자연키 = 기업 + 유형 + 근거 키**이며, 지문과 AI 출력의 신호 참조는 모두 이 자연키를 쓴다. 대리키는 신호를 다시 계산할 때마다 바뀔 수 있으므로 참조에 쓰지 않는다 |
| 성격 | **상태**(현재 어떤 상태인가) 또는 **변화**(최근 무엇이 바뀌었거나 예정되었나) |
| 방향 | 긍정, 부정, 불확실. **실적과 재무 건전성, 상장 유지·정상 거래에 대한 영향** 기준이며 주가 영향이 아니다([D-66](../decisions/D-60-D-99.md)). 상황에 따라 방향이 달라지는 유형은 불확실로 둔다 |
| 심각도 | 낮음, 중간, 높음. 규칙이 계산값(변화 폭, 매출 대비 금액 비중 등)으로 정한다 |
| 발생 기준일 | 변화가 일어난 시점. 재무 신호는 해당 재무 기간의 종료일, 공시 신호는 공시 접수일이다. "언제 변했는가"(product.md §4)에 답하고 타임라인 정렬 기준이 된다 |
| 지속 | 같은 방향의 변화가 연속으로 나타난 기간 수(예: 매출 감소 3분기 연속). 판정 방법은 §3.7. 재무 신호만 해당하며 코드가 계산한다. "일시적인가, 지속적인가"(product.md §4)의 판단 근거다 |
| 계산값 | 판정에 쓴 수치. 자리표시자 키와 값 |
| 확인 지표 | 이 신호가 있을 때 앞으로 지켜볼 지표 키 |
| 상태 | 신호 계산 때마다 다시 판정한다([D-36](../decisions/D-01-D-40.md)). **활성**: 지금도 성립(변화 신호는 최신 재무 기간에서 나온 것, 상태 신호는 최신 기간에도 조건이 이어지는 것). **이력**: 그 기간에는 성립했고 지금은 최신이 아님. **철회**: 다시 계산했더니 같은 자연키로 성립하지 않음(정정·규칙 변경). **행은 지우지 않는다.** 이력은 타임라인에 쓰고, 철회는 화면·AI 입력에서 뺀다 |
| 규칙 버전 | 판정에 쓴 규칙 카탈로그 버전. 버전이 바뀌면 전체를 다시 판정한다 |

규칙 카탈로그(유형, 판정 조건, 성격, 방향, 심각도 기준, 확인 지표)는 코드로 관리한다. 유형별 쉬운 설명은 정적 콘텐츠로 관리한다.

### 3.2 화면 배치

| 섹션 | 사용하는 신호 |
|---|---|
| 최근 변화 (타임라인) | 성격이 변화인 신호(활성·이력, 최근 N개 기간)와 향후 이벤트가 아닌 지난 이벤트. 발생 기준일 순. 철회 신호와 데이터 한계 신호는 넣지 않는다 |
| 앞으로 지켜볼 점 (향후 전망) | 활성 변화 신호의 확인 지표, 방향이 불확실인 신호(모든 성격), 향후 이벤트 |
| 리스크 | 성격이 상태이고 방향이 부정인 활성 신호 |

데이터 한계 신호(방향 불확실)는 향후 전망의 "해석할 때 참고할 점"과 재무 섹션의 참고 표시로만 쓴다.

리스크와 향후 전망은 성격과 방향으로 나눠 같은 신호가 중복되지 않게 한다. 최근 변화 타임라인은 이력이므로 향후 전망의 긍정·부정 신호와 같은 신호를 보여 주되, 향후 전망에서 만든 신호별 설명을 그대로 재사용한다 (architecture.md §6.2).

### 3.3 변화와 근거의 연결 (코드)

"무엇과 관련되어 있는가"(product.md §4)는 코드가 연결한다. AI는 코드가 연결한 근거를 설명할 뿐 스스로 연결하지 않는다.

- 재무 신호에는 같은 재무 기간(기간 시작일 ~ 해당 정기보고서 접수일) 안에 접수된 해당 기업의 주요 공시를 연결한다.
- 공시 신호에는 그 공시 자체와, 이후 처음 나온 정기보고서의 재무 변화 신호를 연결한다.
- 연결은 저장하지 않고 조회·입력 구성 시점에 계산한다. 규칙이 바뀌어도 데이터를 다시 만들 필요가 없게 하기 위함이다.
- 연결은 "같은 시기에 함께 일어났다"는 사실이며 인과를 뜻하지 않는다. 인과 서술 규칙은 §7.2를 따른다.
- 정정 공시는 원 공시와 한 묶음으로 본다([D-31](../decisions/D-01-D-40.md)). 연결·입력에는 묶음당 한 건만 넣고, 보고서명과 내용은 최신본, 시점은 원 공시 접수일을 쓴다. 같은 사건이 정정 횟수만큼 반복되어 보이지 않게 하기 위함이다.

| 데이터 한계 | 재무 이력 부족, 금융업 지표 해석 제한, 매출액 없음, 재무 기준 전환, 결산기 변경, 재무 데이터 불일치, 최신 재무 미확인, 사업보고서 오래됨, 정정공시 빈번 | 상태 | 불확실 | — |
| 데이터 한계 | 긍정·부정 신호 상충 | 상태 | 불확실 | — |

- 공시 신호의 근거 키는 원 공시의 공시번호이고 발생 기준일은 원 공시 접수일이다. 정정 공시로 별도 신호를 만들지 않고, 정정으로 내용이 바뀌면 최신본으로 다시 판정한다. "정정공시 빈번"은 코드가 기간 안의 정정 표시 공시 수로 판정한다.
- 공시 기반 신호 중 금액 비교가 필요한 유형은 OpenDART 구조화 API로 제공되는 것부터 구현한다. 나머지는 공시 유형(제목) 기준으로 판정한다.
- 공급계약 체결은 거래소 공시라서 구조화 API가 없다. 공시 문서의 "매출액 대비" 항목을 추출해 심각도를 정하고, 추출에 실패하면 심각도를 낮음으로 둔다.
- 시장경보(투자주의·경고·위험)·매매거래정지는 신호로 만들지 않고 거래 상태 사실로 보인다(§3.12, [D-68](../decisions/D-60-D-99.md)).
- 공시 신호 채택 기준, 신호로 만들지 않는 공시(무상증자·병합·분할은 이벤트, 자기주식·배당·지분 사건은 주주 관점 영역 설계 뒤, 회사의 실적 전망 공시와 안내·절차성 공시는 목록에만), 종속·자회사 공시 제외는 [D-66](../decisions/D-60-D-99.md)을 따른다. 해제·종결 공시는 상태 신호를 이력으로, 취소·철회 공시는 철회로 만든다.
- 재무 신호의 판정 조건·심각도·근거 키·지속은 §3.7을 따른다([D-35](../decisions/D-01-D-40.md)). 초안의 "매출 성장 가속·둔화"와 "높은 부채비율"은 뺐다.
- **동종업계 정의**: 확정 경쟁사가 3개 이상이면 확정 경쟁사를 쓴다. 아니면 산업코드 중분류(앞 2자리)가 같은 기업 중 매출액 상위 10개를 쓴다. 비교 대상이 5개 미만이면 업계 비교 신호를 만들지 않는다. 업계 기준값은 중앙값을 쓴다.

### 3.5 재무 지표의 원천 (코드)

재무 신호와 재무 쉬운 설명의 숫자는 모두 코드가 `financial_line`(주요계정 원천 행)에서 계산한다. 저장 형태와 기간 규칙은 architecture.md §4.2·§4.3과 [D-32](../decisions/D-01-D-40.md)·[D-33](../decisions/D-01-D-40.md)을 따른다.

| 지표 키 | 원천 계정명 | 규칙 |
|---|---|---|
| 매출액 | 매출액 | 금융형은 없을 수 있다 |
| 영업이익 | 영업이익, 영업이익(손실) | 두 이름은 같은 계정이다(같은 기업도 연결·별도에서 이름이 다를 수 있다) |
| 당기순이익 | 당기순이익(손실) | 한 보고서에 두 번 나온다(실제 26/26건 같은 값). 순서(`ord`)가 작은 행을 쓰고, 값이 다르면 경고를 남긴다 |
| 자산총계·부채총계·자본총계·자본금 | 같은 이름 | 자본잠식은 자본총계와 자본금으로 판정한다 |
| 유동자산·유동부채 | 같은 이름 | 유동비율([D-47](../decisions/D-41-D-53.md)). 일반형에만 있다 |
| (형식 판별) | 유동자산 | 있으면 일반형, 없으면 금융형 |
| 영업·투자·재무활동 현금흐름, 기말 현금 | 전체 재무제표 API 현금흐름표의 **표준 계정 ID**: `ifrs-full_CashFlowsFromUsedInOperatingActivities`, `ifrs-full_CashFlowsFromUsedInInvestingActivities`, `ifrs-full_CashFlowsFromUsedInFinancingActivities`, `dart_CashAndCashEquivalentsAtEndOfPeriodCf` | 계정명으로 찾지 않는다. 분기·반기 값은 회계연도 누적이다. 주요계정 보고서와 공시번호·통화가 같을 때만 쓴다([D-48](../decisions/D-41-D-53.md)) |

- 계산 지표: 영업이익률(영업이익 ÷ 매출액), 부채비율(부채총계 ÷ 자본총계), 전년 동기 대비 증가율, 4분기 단독값. 모두 읽을 때 계산하고 저장하지 않는다.
- 전년 동기 대비는 같은 보고서의 당기·전기 값으로 계산한다(분기: 3개월 단독끼리, 누적끼리. 연간: 당기·전기·전전기). 4분기는 파생값(연간 − 3분기 누적)이며 전년 대비 비교를 하지 않는다(§3.6, D-35).
- 지표에 필요한 계정이 없으면 그 지표와 그 지표를 쓰는 신호를 만들지 않는다. 값을 추정하지 않는다.
- 금융형: "금융업 지표 해석 제한" 신호를 둔다. 매출액이 있어도 이자·수수료·금융상품 손익을 합친 영업수익이므로 "영업수익"으로 표시하고, 매출 기반 신호(매출 증감, 영업이익률)와 부채비율 신호를 만들지 않는다. 흑자·적자 전환은 연간으로만, 영업적자 지속과 자본잠식은 일반형과 같다 ([D-35](../decisions/D-01-D-40.md)).
- 매핑에 없는 계정(이자수익, 예수부채, 보험계약부채 등)은 저장만 하고 MVP 지표에 쓰지 않는다. 금융업 전용 지표는 필요가 확인되면 추가한다.
- 주요계정 API에는 "영업수익"이라는 계정명이 없다(2026-09-25, 저장된 계정 행 298,265건 전수 확인: 매출 계열은 "매출액" 26,600행뿐). 금융형 중 증권·투자사는 "매출액"으로 오고 화면·AI에서는 "영업수익"이라는 이름으로 보여 주며(금융형 56개사 중 27개사), 은행·보험은 매출 계정이 없다(`ACCOUNT_MISSING`). 매핑에는 실제 응답에서 확인한 계정명만 추가한다.
- 시계열은 최신 기간의 기준(연결/별도)·통화로 고정하고, 그 기준이 없는 기간은 빈 기간으로 둔다([D-37](../decisions/D-01-D-40.md)). 12개월이 아닌 회계연도는 비교하지 않는다. 둘 다 "데이터 한계" 신호의 근거로 쓴다.
- 금액을 기업끼리 비교(매출액 순위, 동종업계 매출 상위)할 때는 원화 기업만 쓴다. 비율 비교는 통화와 무관하다.

### 3.6 재무 지표 (코드, 읽을 때 계산)

지표는 저장하지 않고 화면·신호 계산·AI 입력을 만들 때 원천 행(`financial_line`, 현금흐름표 행)에서 계산한다. 이 표에 없는 지표(순이익률, ROA, EPS·BPS, 잉여현금흐름 등)는 만들지 않는다([D-47](../decisions/D-41-D-53.md)). PER·PBR 등 시장 가격이 필요한 밸류에이션 지표는 핵심 범위에 두지 않는다([D-49](../decisions/D-41-D-53.md)). ROE·유동비율·현금흐름은 [D-47](../decisions/D-41-D-53.md)·[D-48](../decisions/D-41-D-53.md)로 추가하는 지표이며 아직 구현하지 않았다.

| 지표 키 | 정의 | 기간 | 비교 | 계산하지 않는 경우 (사유 코드) |
|---|---|---|---|---|

- **기간과 비교** ([D-33](../decisions/D-01-D-40.md)·[D-35](../decisions/D-01-D-40.md))
  - 분기 시계열: 1분기(1분기 보고서 당기), 2분기(반기 보고서 당기 = 3개월), 3분기(3분기 보고서 당기), 4분기(연간 − 3분기 누적, 파생값). 비12월 결산도 회계연도 시작일 기준으로 1~4분기를 센다(기간 키·계산의 기준). 표시 라벨은 모든 자리가 한 규칙을 쓴다: 비12월 결산의 분기는 회계연도 분기 번호 없이 달로("2026년 4~6월"), 12개월이 아닌 회계연도는 실제 기간으로 쓴다([D-59](../decisions/D-54-D-59.md)·[D-62](../decisions/D-60-D-99.md), §4.4.2의 "기간 라벨").
  - 전년 동기 비교는 같은 보고서의 당기·전기 값으로만 한다. 4분기 파생값은 추이 표시와 영업적자 지속 계산에만 쓰고, 전년 대비 비교를 하지 않는다(연간 비교가 대신한다).
  - 4분기 파생값은 사업보고서와 3분기 보고서의 기준·통화·회계연도 시작일이 같고, 파생 매출이 0 이상일 때만 쓴다(아니면 `DERIVED_INVALID`, 실제 12개사).
  - 전분기 대비는 계절성이 커서 변화율로 계산하지 않는다. 추이는 분기 값을 순서대로 보여 준다.
- **시계열 기준**: 최신 기간의 기준(연결 우선)·통화로 고정한다. 그 기준이 없는 기간은 빈 기간(`BASIS_GAP`)이다 ([D-37](../decisions/D-01-D-40.md)).
- **범위**: 최근 12분기와 3개 사업연도(사업보고서의 당기·전기·전전기로 3년 연간 값을 얻는다).
- **데이터 점검**: 보고서마다 자산총계 = 부채총계 + 자본총계(차이 0.5% 이내)를 확인한다. 어긋나면(실제 5벌) 그 기간의 재무상태표 지표와 신호를 만들지 않고 `INCONSISTENT_BALANCE`로 둔다.
- **비원화**: 지표는 그 통화로 계산하고 환산하지 않는다. 원화 기준값이 필요한 매출 기반 신호와 매출 증가율은 만들지 않는다(`NON_KRW`). 영업이익률·부채비율처럼 기준값이 필요 없는 비율은 계산한다. 금액 표시는 [D-41](../decisions/D-41-D-53.md).

### 3.7 재무 신호 판정 (코드)

[D-35](../decisions/D-01-D-40.md)의 결정을 구현하는 규칙이다. 문턱값·심각도 구간은 규칙 카탈로그(코드)의 초기값이며 규칙 버전과 함께 관리한다. 초기값의 근거는 2026-09-25 로컬 데이터 분포다(work/3-collection-signals.md §6).

**공통**

- 판정 단위는 재무 기간 하나(보고서 하나)다. 1분기·반기·3분기 보고서는 분기 3개월 값, 사업보고서는 연간 값으로 판정한다. 한 기간에 한 유형은 최대 한 건이다.
- 대상은 시계열 기준의 최근 12분기와 3개 사업연도다. 계산할 때마다 기업의 대상 기간 전체를 다시 판정하고 자연키로 반영한다(없어진 것은 철회, [D-36](../decisions/D-01-D-40.md)).
- 기준값: 매출 비교는 전년 동기 매출이 분기 10억 원, 연간 40억 원 이상일 때만 한다.
- 근거 키: 변화 신호는 `회계연도 시작일:기간 구분`(예: `2026-01-01:H1`), 상태 신호는 조건이 이어진 구간의 첫 기간 키, 부채비율 급등은 `회계연도 시작일:FYDEBT`(같은 회계연도 안에서는 한 건).
- 발생 기준일: 변화 신호는 기간 종료일, 상태 신호·부채비율 급등은 조건이 처음 성립한 기간의 종료일.
- 근거 공시: 그 기간 보고서의 `receipt_no`(최신 정정본)를 계산값에 남긴다. 화면·AI에는 그 공시가 속한 정정 묶음(원 공시 + 정정, D-31)과 §3.3으로 연결한 같은 시기 공시를 준다.
- 지속: 매출 증감·영업이익률 변화 신호는 이번 기간을 포함해 직전 기간들에서 같은 방향(부호 기준, 문턱값 아님)의 전년 동기 변화가 이어진 수. 분기 신호는 분기끼리, 연간 신호는 연간끼리 센다. 비교하지 않는 기간(4분기 파생값 등)이나 빈 기간에서 끊긴다. 흑자·적자 전환과 부채비율 급등은 지속을 두지 않는다(영업이익의 연속은 영업적자 지속이 말하고, 부채비율은 분기마다 같은 기준점과 비교해 셈이 무의미하다, [D-61](../decisions/D-60-D-99.md)). 상태 신호는 조건이 이어진 분기 수. 재무 쉬운 설명의 흐름 사실(§4.4.2)도 같은 셈이다.
- 계산값: 현재값, 전년 동기(또는 전기말) 값, 변화량, 기준(연결/별도), 통화, 기간 라벨, 출처 공시번호를 자리표시자 키와 값으로 남긴다.

| `FIN_DATA_IRREGULAR_PERIOD` | 최근 3개 사업연도에 12개월이 아닌 회계연도(결산기 변경) |
| `FIN_DATA_INCONSISTENT` | 최신 기간의 자산총계 ≠ 부채총계 + 자본총계 |
| `FIN_DATA_STALE` | 최신 기간 P 다음 보고서의 기한일(다음 기간 종료 월의 말일 + 분기·반기 60일, 사업 120일, 상장사에 적용되는 가장 긴 기한)에 7일을 더한 날이 지났는데 P보다 뒤 기간의 보고서가 수집되지 않음. 달력일로 세고 휴일은 따지지 않는다. 근거 키는 P. 다음 보고서가 수집되면 이력, 규칙 변경 등으로 같은 P에서 성립하지 않으면 철회. 시간이 지나 판정이 바뀌는 날에만 다시 판정한다([D-43](../decisions/D-41-D-53.md)). "미제출"이 아니라 "수집 기준 미확인"으로 표현한다 |

- 이름·설명은 사실만 말한다. "위험", "좋다·나쁘다", 투자 관련 표현을 쓰지 않는다. 방향은 실적·재무 건전성에 대한 영향 기준이다(§3.1).

### 3.8 재무 결과 구조 (코드 → 화면·AI)

코드는 기업마다 아래 구조의 **재무 요약**을 만든다. 화면과 AI 입력은 같은 구조를 쓴다. 숫자는 모두 자리표시자 키로 참조한다(D-17).

| 부분 | 내용 |
|---|---|
| 기본 | 시계열 기준(연결/별도), 통화, 재무제표 형식(일반/금융), 최신 기간(키·라벨·종료일·출처 공시번호) |
| 플래그 | 사유 코드 목록(`NON_KRW`, `BASIS_GAP`, `DERIVED_INVALID`, `SMALL_BASE`, `INCONSISTENT_BALANCE`, `NOT_APPLICABLE_FORMAT` 등)과 해당 기간. 사유별 쉬운 설명은 정적 콘텐츠 |
| 분기 | 최근 12분기(화면·신호 판정). AI 입력에는 분기 시계열을 넣지 않는다(§4.4.2, [D-38](../decisions/D-01-D-40.md)). 기간마다 키, 라벨, 종료일, 출처(공시번호 또는 파생), 지표별 {값, 전년 동기 값, 변화량, 단위, 상태 또는 사유 코드} |
| 연간 | 최근 3개 사업연도. 분기와 같은 형식 |
| 재무상태 | 기간 말 자산·부채·자본·자본금, 부채비율과 전기말 대비 변화, 잠식률 |
| 신호 | 대상 기간의 활성·이력 재무 신호(자연키, 유형, 방향, 심각도, 발생 기준일, 지속, 계산값, 확인 지표, 근거 공시) |

- 자리표시자 키: `fin.{지표}.{기간 키}`, 변화량은 `fin.{지표}_yoy.{기간 키}`(증가율 %) 또는 `fin.{지표}_diff.{기간 키}`(%p). 기간 키는 `회계연도 시작 연월.분기`(예: `2026-01.Q2`, 연간은 `2025-01.FY`).
- 표시 형식은 코드가 정한다: 금액은 한국어 수 단위(조·억·만)와 통화명(원·위안·달러·엔·파운드, 그 밖은 통화 코드), 비율은 소수 한 자리 %, 차이는 %p. 표시 문자열은 렌더링할 때 원값으로 만든다([D-41](../decisions/D-41-D-53.md)). 기준값 미만 증가율처럼 계산하지 않은 값은 숫자 대신 사유 코드가 들어가고, AI는 그 값을 언급하지 않는다.
- 이 구조는 화면과 신호 계산의 기준이다. AI 입력은 이 구조에서 코드가 골라 만든 사실표다(§4.4.2). 신호가 없는 기간을 AI가 변화로 서술하거나, 계산하지 않은 비교를 만들지 않는다.
- [D-47](../decisions/D-41-D-53.md)·[D-48](../decisions/D-41-D-53.md)을 구현하면 분기·연간 기간에 유동자산·유동부채, 연간에 ROE 입력(전전기말 자본총계), 기간별 현금흐름(누적 기간 키)이 더해진다. 현금흐름은 손익과 기간의 뜻이 다르므로(누적) 분기 기간과 섞지 않고 따로 둔다.

### 3.9 지표 보기 (코드 → 화면, [D-47](../decisions/D-41-D-53.md))

재무 섹션은 지표를 나열하지 않고 **지표 보기** 단위로 보여 준다. 지표 보기는 코드가 모두 만들고, AI는 관여하지 않는다(재무 쉬운 설명은 이 중 일부 사실만 쓴다, §4.4). 이 절은 정보 구조이며 화면 배치는 화면 설계에서 정한다. 판정 표시는 [D-60](../decisions/D-60-D-99.md), 지표별 비교는 [D-61](../decisions/D-60-D-99.md), 표시 일치(기간 라벨·비교 기준·부호)는 [D-62](../decisions/D-60-D-99.md)를 따른다.

**묶음과 지표**

| 묶음 | 지표 | 사용자가 얻는 답 |
|---|---|---|
| 성장 | 매출액·매출 증가율(금융형은 영업수익, 증가율 없음), 영업이익, 당기순이익 | 얼마나 팔고 벌었나, 전년 같은 기간보다 늘었나 |
| 수익성 | 영업이익률(일반형), ROE(연간) | 판 것·가진 자본에 비해 얼마나 남겼나 |
| 안정성 | 부채비율(일반형), 유동비율(일반형), 자본총계·자본금(잠식) | 빚이 자본에 비해 얼마나 되나, 1년 안에 갚을 빚을 감당할 자산이 있나 |
| 현금흐름 | 영업·투자·재무활동 현금흐름, 기말 현금(일반형) | 이익이 현금으로 들어왔나, 번 돈을 어디에 쓰나 |

**지표 보기의 구성**

| 부분 | 내용 | 만드는 곳 |
|---|---|---|
| 정의 | 쉬운 말 한두 문장(예: "ROE는 회사가 가진 자기 돈(자본)으로 1년에 얼마를 벌었는지예요") | 정적 콘텐츠 |
| 현재 값 | 값, 기간 라벨(누적이면 "1~6월"), 기준(연결/별도), 통화, 출처 공시 | 코드 |
| 비교 | 지표마다 정한 기준(전년 같은 기간 또는 직전 사업연도 말)의 값, 변화량(%·%p·금액), 산술 방향(늘었다·줄었다·같다), 같은 방향이 이어진 기간 수. 무엇을 쓸 수 있는지는 지표별로 다르다: 부호가 바뀔 수 있는 금액은 두 값이 모두 양수일 때만 방향을 말하고, 이어진 기간 수는 뜻이 있는 지표에만 쓴다([D-61](../decisions/D-60-D-99.md)). 기준의 종류·시점이 보이고, 부호와 증감 어휘를 겹쳐 쓰지 않는다([D-62](../decisions/D-60-D-99.md)) | 코드 |
| 큰 변화 여부 | 이 지표를 **근거 지표**로 하는 활성 신호가 있으면 신호 배지(확인 지표는 "앞으로 지켜볼 점"에서만 쓴다). 없으면 네 상태를 구분한다: 신호 있음 / 판정했고 성립하지 않음("규칙상 큰 변화로 표시되지 않음"은 이 상태에만) / 판정 대상 아님(사유) / 판정 규칙 없음([D-60](../decisions/D-60-D-99.md)) | 코드(신호) |
| 해석 참고 | 지표별 정적 문구(예: "업종에 따라 보통 수준이 크게 달라요", "현금흐름은 계절에 따라 누적 중간에 마이너스가 되기도 해요") | 정적 콘텐츠 |
| 계산하지 않음 | 숫자 대신 사유 코드의 정적 문구. 사유는 값·비교·판정 자리에 따로 둔다(값은 있고 비교만 없으면 값은 보인다, [D-60](../decisions/D-60-D-99.md)) | 코드 + 정적 콘텐츠 |

- 산술 방향은 좋고 나쁨이 아니다. 좋고 나쁨의 방향(§3.1)은 신호에만 있다. 신호가 없는 변화에 색·아이콘으로 평가를 덧씌우지 않는다.
- 부호로 정해지는 사실(흑자·적자, 현금 유입·유출, 자본잠식)은 코드가 사실로 표시한다. 수준 판정(높다·낮다·양호·위험), 묶음별·종합 점수, 등급은 만들지 않는다.
- 업종 맥락은 동종업계 정의(§3.4)를 구현한 뒤 동종업계 중앙값을 "참고 값"으로 나란히 두는 방식으로만 준다. 순위·평가어는 붙이지 않는다.
- **요약 재무제표**는 지표의 근거로 둔다. 손익(매출액·영업이익·당기순이익), 재무상태(유동자산·자산총계·유동부채·부채총계·자본금·자본총계), 현금흐름(세 합계·기말 현금)의 최신 기간과 비교 기간 값이다. 전체 재무제표는 출처 공시 링크로 대신한다.
- 계산할 수 없거나 데이터가 부족하면 값을 추정하거나 빈칸으로 두지 않는다. "계산하지 않음"과 사유를 보여 준다. 기업 전체에 걸친 한계는 데이터 한계 신호(§3.7)의 문구로 보여 준다.
### 3.10 향후 이벤트 유형 (코드, [D-66](../decisions/D-60-D-99.md))

`corporate_event`는 방향 없이 **공시로 날짜가 확정된 일**(또는 법정 기한)만 담는다. 예측·추정 날짜는 쓰지 않는다.

| 유형 | 날짜의 근거 |
|---|---|
| 주주총회 | 주주총회 소집 결의 |
| 배당 기준일 | 주주명부 기준일 설정·배당 기준일 결정 |
| 신주 상장 예정일 | 유상·무상증자 결정 |
| 전환·행사 청구 기간 시작 | CB·BW·EB 발행 결정 |
| 합병·분할 기일 | 합병·분할 결정 |
| 감자·주식병합·액면분할의 효력일, 그에 따른 거래정지 예정 기간 | 각 결정 공시 |
| 정기보고서 제출 기한 | 법정 기한(§3.7 `FIN_DATA_STALE`과 같은 기한 규칙) |

- 정정으로 날짜가 바뀌면 최신본을 쓰고(D-31), 취소·철회되면 내린다.
- 날짜가 지나면 "앞으로 지켜볼 점"에서 빠지고 최근 변화 타임라인에 방향 없는 사건으로 남는다. 정기보고서 제출 기한은 타임라인에 남기지 않는다.
- 넣지 않는 것: IR 개최, 공시로 확정되지 않은 실적 발표 예정일, 보호예수 해제일.

### 3.11 잠정실적 (코드, [D-67](../decisions/D-60-D-99.md))

- 잠정실적(영업(잠정)실적 공정공시)은 **재무 데이터가 아니라 공시 사실**이다. 재무 원천은 정기보고서뿐이다(D-32~D-34).
- 잠정 수치는 재무 요약·지표 보기·추이, 신호, 모든 AI 입력, 시장 평가에 쓰지 않고 화면에 옮기지 않는다. 원문 링크로 본다.
- 최신 정기 재무 보고서의 접수일보다 뒤에 접수된 그 기업의 잠정실적 공시가 있으면, 재무 섹션 맨 위에 코드가 알린다: 회사가 더 최신 실적(잠정)을 공시했고(날짜·원문), 아래 재무는 정기보고서 기준 어느 기간이며, 정기보고서가 나오면 반영된다. 정기보고서가 수집되면 사라진다. 재무 쉬운 설명은 내리지 않는다(D-42).
- 최근 변화 타임라인에 방향 없는 사건으로 둔다.
- 자회사의 잠정실적과 회사의 실적 전망 공시는 쓰지 않는다. `FIN_DATA_STALE`(D-43)과는 따로 판정한다.

### 3.12 거래 상태 (코드, [D-68](../decisions/D-60-D-99.md))

- 거래소가 정한 "지금 거래 조건"의 사실이다: 매매거래정지(기간·해제), 관리종목·투자주의환기종목 지정, 불성실공시법인 지정 예고, 거래소 안내(관리종목 지정 우려, 투자유의 안내 등), 상장폐지 절차, 시장경보, 상장폐지.
- 매매거래정지·시장경보·거래소 안내·지정 예고는 신호가 아니다. 관리종목·투자주의환기종목 지정은 같은 사실을 리스크의 상태 신호(§3.4)가 함께 쓴다.
- 지정·해제·기간·근거·기준일만 보이고, 뜻은 정적 콘텐츠, 사유는 원문 제목과 링크다. 해제를 추정하지 않는다.
- 표시가 없는 것을 "정상"이라고 말하지 않는다.
- 매매거래정지·시장경보·거래소 안내는 타임라인에 넣지 않는다. 어떤 AI 분석의 입력에도 넣지 않는다.
- OpenDART 공시로 얻는 상태는 핵심 범위, 얻지 못하는 상태(시장경보 등)는 선택 모듈 조건(D-22)이다.
