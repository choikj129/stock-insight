# 재무 쉬운 설명 명세 (`financial_explain`)

> 원본: `ai-analysis.md` §4.4 (2026-09-27 분리). 이 파일의 § 번호는 원본 번호를 그대로 쓴다. 번호와 파일의 대응은 [문서 지도](../README.md#4-옛-참조와-새-위치).

### 4.4 재무 쉬운 설명 (`financial_explain`)

| 항목 | 내용 |
|---|---|
| 목적 | 기업의 최근 재무 상태와 중요한 변화를 "무엇이 언제 얼마나 변했나"와 항목 사이의 관계로 쉽게 설명한다 |
| 입력 | 코드가 만든 설명용 사실 묶음(§4.4.2, [D-38](../decisions/D-01-D-40.md)). 원천 행·분기 시계열·원문은 넣지 않는다 |
| 출력 | 섹션 4개의 짧은 글. 숫자·기간·신호는 토큰으로만 쓴다(§4.4.4, [D-39](../decisions/D-01-D-40.md)) |
| 지문 | 입력에 쓴 원천 식별자 집합(§4.4.6, [D-40](../decisions/D-01-D-40.md)) |
| 대상·시점 | AI 적용 대상 + 골든셋. 재무 신호 계산(07:00) 뒤 분석 동기화 실행에서 |

#### 4.4.1 역할과 경계

| 코드 | AI |
|---|---|
| 지표·변화량 계산, 계산할 수 없는 지표와 사유 판단 | — |
| 신호 판정, 입력에 넣을 신호 선별, 기간·주제로 묶기, 순서 정하기 | 묶음 순서대로 문장으로 풀어 쓰기 |
| 쓸 섹션 결정, 변화 유무(`change_status`) 결정 | 정해진 섹션만 채우기 |
| 기간 라벨, 숫자 표시 형식, 기준(연결/별도)·통화·기준일·출처 공시 표시, 데이터 한계 문구 | — |
| 검증, 게시 판단 | — |

AI는 새 계산(합계·차이·평균·배수·순위), 새 비교(전분기 대비, 기업 간 비교), 새 판정(중요도, 좋다·나쁘다), 원인 추정, 미래 서술을 하지 않는다. 재무 쉬운 설명에는 원문 입력이 없으므로 원인을 서술할 근거가 없다(§7.2 "왜" 규칙의 (1)이 해당하지 않는다).

#### 4.4.2 입력 (코드가 구성)

> 현재 계약: [D-54](../decisions/D-54-D-59.md)(섹션 배정)·D-54 보완(모든 섹션 사실 배정, `history` 시간순)·[D-55](../decisions/D-54-D-59.md)(관계 서술)·[D-59](../decisions/D-54-D-59.md)(표시 문자열 제거, 사실 이름 방향, 12개월이 아닌 회계연도 제외). 2026-09-27 구현(입력 구성 `fx-input-6`, 프롬프트 `fx-v13`, 검증기 `fxv-8`, work/3-4-verification-2.md §7.4.34). 골든셋 실제 재검증 자동 검증 11/12, 첫 시도 규칙 3(라벨·표시 값 복사) 0/12(§4.4.8 사람 검토는 2026-09-27 이 결과로 마쳤다 — work/3-4-verification-2.md §7.4.35. 820 거절 1건이 남아 골든셋 전체 자동 검증 통과는 아니고, 게시는 꺼져 있다). 이전에 저장된 입력에는 없는 필드가 있다: `fx-input-2` 이하는 `section`·`sectionFacts`, `fx-input-3` 이하는 `relations`, `fx-input-3`은 `sectionFacts`가 `overview`·`structure`뿐이다. `fx-input-5` 이하는 `facts[].display`·`periods[].label`이 있고 `periods[].kind`가 없다.

```
company        { name, format: GENERAL|FINANCIAL, currency, basis: CFS|OFS, fiscalYearEndMonth }
latest         { period: "2026-01.Q2", kind: QUARTER|ANNUAL }
changeStatus   CHANGED | NONE
sections       ["overview", "sales_profit", "structure", "history"]   // 코드가 정한 포함 여부·순서
periods        [{ key: "2026-01.Q2", kind: QUARTER|ANNUAL }, ...]      // {per.*} 대상. 라벨·표시 값은 없다(D-59) —
                  // 렌더링할 때 코드가 만든다. 12개월이 아닌 회계연도(결산기 변경)는 실제 기간으로, 비12월 결산
                  // 분기는 회계연도 분기 번호 없이 달로만 렌더링된다(예: "2026년 4~6월")
facts          [{ key: "fin.revenue_yoy.2026-01.Q2", name: "매출 증가율(전년 같은 분기 대비)",
                  sign: "+", period: "2026-01.Q2" }, ...]
                  // 사실표 = sectionFacts의 합집합. 흑자·적자 상태·전환 사실도 사실이다(표시는 렌더링할 때 만든다,
                  // D-55·D-59 — AI는 값을 몰라도 정해진 문형이 방향과 무관하게 성립한다). 이름의 방향(증가율/감소율,
                  // 상승폭/하락폭)은 실제 부호를 따른다(D-59)
signals        [{ ref: "S1", type, status: ACTIVE|PAST, nature, direction, severity, period,
                  section: sales_profit|structure|history, persistence, factKeys: [...] }, ...]
                  // period = 설명 기준 기간(활성: 최신 기간, 이력: 성립 기간), section = 코드가 정한 섹션 (D-54)
groups         [{ section, period, topic: SALES_PROFIT|STRUCTURE, refs: ["S1","S2"], mixedDirection }, ...]
sectionFacts   { overview: [...], sales_profit: [...], structure: [...], history: [] }
                  // 섹션마다 쓸 수 있는 사실 키. 코드가 상한 이하로 배정, 한 사실은 한 섹션에만 (D-54, D-54 보완)
relations      [{ type: OPERATING_INCOME_DIRECTION, factKeys: [최신 영업이익, 전년 영업이익], value: UP|DOWN|SAME },
                { type: STATE_DIFFERENCE, factKeys: [순이익 상태·전환 사실, 최신 영업이익], value: DIFFERENT }]
                  // 코드가 판정한 관계(D-55 R2·R5). 토큰이 아니고 값 스냅샷에도 없다. 두 사실이 모두 배정됐을 때만
unavailable    [{ metric: "revenue_yoy", reason: "SMALL_BASE" }, ...]      // 설명하면 안 되는 지표
doNotMention   ["부채비율", ...]                                         // 형식·통화별 금지 용어
```

**사실표(`facts`)의 후보** — 계산식·사유 코드는 §3.6, 신호 계산기와 같은 코드를 쓴다. 코드는 아래 후보를 계산한 뒤 **섹션에 배정된 것만** 사실표에 넣는다(아래 "섹션 배정", D-54 보완). 값 스냅샷도 같은 사실만 담는다.

| 묶음 | 사실 키(지표) | 기간 |
|---|---|---|
| 최신 손익 | `revenue`, `revenue_yoy`, `operating_income`, `operating_income_prior`, `operating_margin`, `operating_margin_diff`, `net_income` (`revenue_prior`·`operating_margin_prior`·`net_income_prior`는 계산하지만 배정하지 않는다: 변화량이 있으면 같은 정보이고, 없으면 코드가 일부러 방향을 주지 않은 경우라 원값 짝이 그 방향을 되살린다, D-35·D-41) | 최신 보고서가 분기(1분기·반기·3분기)면 그 분기 3개월, 사업보고서면 연간. 파생 4분기는 최신 손익으로 쓰지 않는다 |
| 흑자·적자 ([D-55](../decisions/D-54-D-59.md)) | `net_income_status`(표시 "흑자"/"적자", 순이익에만), `operating_income_turn`·`net_income_turn`(표시 "적자에서 흑자로"/"흑자에서 적자로") | 최신 기간. 상태는 값이 0이 아닐 때, 전환은 같은 보고서의 최신·전년 같은 기간 부호가 다를 때(둘 다 0이 아님)만. 전환은 신호와 무관한 부호 사실이다(D-54 보완 "전환의 정의") |
| 연간 | `revenue`, `revenue_yoy`, `operating_income`, `operating_margin`, `net_income` | 최근 3개 사업연도, 각 사업보고서의 당기·전기 |
| 최신 재무상태 ([D-54](../decisions/D-54-D-59.md)) | 일반형: `debt_ratio`, `debt_ratio_diff`(전기말 값이 있을 때) + 활성 자본잠식 신호가 있을 때만 `total_equity`·`capital_stock`. 부채비율을 계산할 수 없는 일반형과 금융형: `total_equity` + (활성 자본잠식이면) `capital_stock`. 최대 4개 = `structure` 상한. `debt_ratio_prior_end`·`total_assets`·`total_liabilities`·`impairment_ratio`는 AI 입력과 값 스냅샷에 넣지 않는다(화면은 재무 요약에서 코드가 보여 준다) | 최신 보고서 기간 말, 변화량은 같은 보고서의 전기말 대비 |
| 흐름 | `revenue_yoy_run`(최신 기간까지 전년 동기 대비 같은 방향이 이어진 분기 수, 부호 포함), `operating_loss_run`(연속 영업적자 분기 수) | 2 이상일 때만. 코드가 센다. `revenue_yoy_run`은 최신 기간의 `revenue_yoy`를 줄 수 있을 때만 준다([D-41](../decisions/D-41-D-53.md)) |
| 신호 근거 | 활성 신호의 `factKeys`가 가리키는 사실(배정된 것만). 이력 신호의 `factKeys`는 비어 있다(`history`는 기간 토큰과 배지로만 쓴다, D-54 보완) | 최신 기간([D-54](../decisions/D-54-D-59.md)) |

- 계산할 수 없는 지표는 사실표에 넣지 않고 `unavailable`에 사유와 함께 넣는다. 금융형은 매출 증가율·영업이익률·부채비율, 비원화는 매출 증가율(기준값이 필요 없는 비율은 계산, [D-41](../decisions/D-41-D-53.md)), 재무상태표 불일치 기간은 재무상태 지표 전체를 뺀다.
- `doNotMention`: 금융형이면 "부채비율", "영업이익률", "매출"(영업수익은 사실 이름 "영업수익"으로만), 매출액이 없는 일반형이면 "매출"을 넣는다. 사실표에 없는 지표 이름이 글에 나오지 않게 하기 위함이다.
- 예상 크기: 사실 25~40개, 신호 8개 이하, 약 2~3천 토큰(시스템 프롬프트 제외).

**신호 선별과 묶음**

- 활성 변화·상태 신호는 모두 넣고, 이력 신호는 입력 범위(최근 8분기·3개 사업연도) 안에서 심각도·최근성 순 최대 4개를 넣는다. 철회 신호와 데이터 한계 신호는 넣지 않는다(데이터 한계는 `unavailable`과 코드 렌더링으로).
- 신호 유형 → 사실 키: 매출 증감 → `revenue`·`revenue_yoy`, 영업이익률 변화 → `operating_margin`·`operating_margin_diff`, 흑자·적자 전환 → `operating_income`·`operating_income_turn`(전환 사실 하나, D-55), 부채비율 급등 → `debt_ratio`·`debt_ratio_diff`, 영업적자 지속 → `operating_loss_run`, 자본잠식 → `total_equity`·`capital_stock`. 활성 신호는 **최신 기간**의 사실을 가리킨다. 상태 신호와 같은 회계연도 동안 활성인 부채비율 급등은 발생 기간이 과거여도 최신 사실로 이어진다([D-54](../decisions/D-54-D-59.md)). 신호의 `calc_values`는 입력에 쓰지 않는다(감사용).
- 신호 `period`와 `section` ([D-54](../decisions/D-54-D-59.md))
  - 활성 신호: `period`는 최신 기간이다. `section`은 주제 섹션이다(손익 → `sales_profit`, 재무 구조 → `structure`).
  - 이력 신호: `period`는 성립 기간, `section`은 `history`다.
  - 조건이 처음 성립한 기간(발생 기준일)은 AI 입력에 넣지 않는다. 배지가 연결되는 타임라인(코드)이 보여 준다.
- 묶음: 같은 섹션·같은 설명 기준 기간·같은 주제(손익: 매출·영업이익률·전환·적자 지속 / 재무 구조: 부채비율·자본잠식)의 신호를 한 묶음으로 둔다. 묶음은 한 섹션 안에서만 만든다. 그래서 활성 신호와 이력 신호가 한 묶음이 되는 일은 없다([D-54](../decisions/D-54-D-59.md)). 묶음은 "같은 시기에 함께 나타난 변화"이며 원인이 같다는 뜻이 아니다.
  - 묶음 안 순서: 흑자·적자 전환 → 매출 → 영업이익률 → 적자 지속.
  - 묶음 간 순서: 활성 변화 → 활성 상태 → 이력. 활성 무리 안에서는 최고 심각도, 최근 기간 순. **이력 묶음은 서술 순서라 설명 기준 기간의 종료일 내림차순(최근 → 과거)**이고 같은 기간끼리만 심각도 순이다(D-54 보완). 이력 신호를 고르는 기준(심각도·최근성 최대 4개)은 그대로다.
  - 방향이 서로 다르면 `mixedDirection = true`.
- **섹션 배정 (`sectionFacts`, [D-54](../decisions/D-54-D-59.md)·D-54 보완)**: 네 섹션 모두 코드가 배정하고, 사실표는 배정의 합집합이다. 한 사실은 한 섹션에만 있다. 금지 용어(`doNotMention`)나 `unavailable`과 이름이 모순되는 사실은 어느 섹션에도 배정하지 않는다.
  - **개요**(상한 3): 코드가 지정한 변화 근거 사실만. `CHANGED`면 첫 묶음 신호의 변화량 사실(`_yoy`·`_diff`), 흑자·적자 전환 신호면 그 전환 사실(2026-09-27 구현 중 보정, D-55 구현 기록). `NONE`이면 매출 증가율 → 영업이익률 변화 → 부채비율 변화 순서로 처음 있는 하나. 없으면 비운다.
  - **`structure`**(상한 4): 위 "최신 재무상태" 구성에서 개요에 지정한 사실을 뺀 나머지.
  - **`sales_profit`**(상한 6): 우선순위대로 채우고 넘치면 뒤를 뺀다. 순이익과 그 상태·전환 사실은 관계 단위라 쪼개지 않는다.
    1. 최신 매출·영업이익(규모)
    2. 이 섹션 활성 신호의 최신 근거 사실(전환 신호면 영업이익 전환 사실)
    3. 순이익 + 상태 또는 전환 사실: 순이익이 전년과 비교해 바뀌었으면 전환, 아니면 영업이익과 상태가 다를 때만 상태
    4. 영업이익률
    5. 흐름 사실: 연속 영업적자 → 매출 연속 흐름
    6. 전년 같은 기간과의 영업이익 비교: 부호가 같으면 전년 영업이익(둘 다 흑자면 방향 관계 R2 함께, 둘 다 적자면 값만), 부호가 바뀌었는데 전환 신호가 없으면 영업이익 전환 사실
    7. 최근 사업연도 사실 하나(최신 기간이 분기일 때만): 매출 증가율, 없으면 영업이익
  - **`history`**: 사실을 배정하지 않는다(빈 목록).
- **관계 항목 (`relations`, [D-55](../decisions/D-54-D-59.md))**: R2(`OPERATING_INCOME_DIRECTION`)는 최신·전년 영업이익이 모두 흑자이고 전년 영업이익이 배정됐을 때 산술 방향을 준다(수치 없음). R5(`STATE_DIFFERENCE`)는 순이익의 상태·전환 사실이 배정됐고 순이익과 영업이익의 흑자·적자가 다를 때 준다.
- `changeStatus`: 활성 **변화** 신호가 하나라도 있으면 `CHANGED`, 없으면 `NONE`(활성 상태 신호만 있어도 `NONE`).
- 섹션: 배정된 사실이나 신호가 있으면 연다.
  - `overview`는 항상 연다.
  - `sales_profit`은 배정된 손익 사실이나 손익 주제의 활성 신호가 있으면 연다.
  - `structure`는 `sectionFacts.structure`나 재무 구조 주제의 활성 신호가 있으면 연다. 최신 재무상태표 불일치로 사실이 없고 활성 신호만 있으면 배지만으로 쓴다(D-52).
  - `history`는 이력(PAST) 신호가 있으면 연다.
  - 흐름 사실(`revenue_yoy_run`, `operating_loss_run`)은 최신 기간까지 이어지는 상태라 그 자체로는 `history`를 열지 않는다([D-45](../decisions/D-41-D-53.md)).

**기간 라벨(코드, [D-59](../decisions/D-54-D-59.md))**: 12월 결산은 "2026년 2분기", "2025년(연간)"(12개월짜리). 그 밖의 결산월은 분기를 달로만("2026년 4~6월" — 회계연도 분기 번호는 흔히 쓰는 달력 분기와 부딪혀 쓰지 않는다), 12개월짜리 연간은 "2025.04~2026.03 회계연도". 12개월이 아닌 회계연도(결산기 변경)는 실제 시작~끝 달로("2025.11~12 회계연도") — "(연간)"이라고 하면 1년 치처럼 읽힌다. 전년 동기는 사실 이름에 "전년 같은 분기"(최신이 분기)·"전년 같은 기간"(최신이 사업보고서)으로 적는다. AI는 기간을 `{per.…}` 토큰으로만 쓰고, 라벨·표시 값은 입력에 없다(D-59) — 렌더링할 때 코드가 만든다.

**넣지 않는 것 (D-38)**: `financial_line` 원천 행과 원천 계정명, 8~12분기 시계열 값(차트는 코드가 그린다), 신호 `calc_values`, 공시번호·공시 제출인·원문, 내부 ID, 철회 신호.

#### 4.4.3 설명 구조와 작성 규칙

| 섹션 | 쓰는 내용 | 분량 |
|---|---|---|
| `overview` | 최신 기간({per})의 한 줄 상태와 변화 유무. `CHANGED`면 첫 묶음의 배지와 `sectionFacts.overview`에 있는 사실을 **하나도 빠짐없이** 쓴다(대개 하나, 첫 묶음에 신호가 둘이면 둘 다 — 지표마다 자기 배지로, [D-57](../decisions/D-54-D-59.md)). `NONE`이면 "{per} 기준으로는 규칙상 큰 변화로 표시된 항목이 없어요"를 쓴다. 사실은 변화량, 전환 신호면 전환 사실만 쓰고, 변화량은 증감 어휘와 함께 변화로 쓴다(예: "영업이익률은 전년 같은 분기보다 {…} 높아졌어요"). "{…} 수준이에요"처럼 변화량을 값으로 쓰지 않는다. 지정된 사실이 없으면 사실 없이 쓴다([D-54](../decisions/D-54-D-59.md). D-46의 "겹치지 않는 원값" 경로는 없앴다). 개요에 쓴 사실은 다른 섹션에서 다시 쓰지 않는다 | 2문장, 사실 토큰 3개 이하 |
| `sales_profit` | `sectionFacts.sales_profit`의 사실과 손익 주제의 활성 신호. 매출(규모) → 영업이익·영업이익률(얼마나 남겼나) → 그 밖의 사실 순서. 순이익은 코드가 배정했을 때만(전환했거나 영업이익과 상태가 다를 때, D-54 보완) 상태·전환 사실 토큰과 함께. 흐름 사실(`revenue_yoy_run`, `operating_loss_run`)은 현재형([D-45](../decisions/D-41-D-53.md)). 최근 사업연도 사실은 그 기간의 `{per}` 토큰으로 가리킨다 | 4문장, 사실 토큰 6개 이하(코드가 6개 이하만 배정) |
| `structure` | `sectionFacts.structure`의 사실과 재무 구조 주제의 활성 신호만. 부채비율(자본에 비해 빚이 얼마나 되나)과 지난 회계연도 말 대비 변화("전기말"은 쓰지 않는다, [D-56](../decisions/D-54-D-59.md)) → 활성 자본잠식 신호가 있을 때만 자본총계·자본금 비교. 금융형은 자본총계(잠식이면 자본금 비교)만. 잠식 신호가 없으면 자본총계·자본금을 비교하지 않는다([D-54](../decisions/D-54-D-59.md)) | 3문장, 사실 토큰 4개 이하(코드가 4개 이하만 배정) |
| `history` | 이력(PAST) 신호만 과거형으로, 입력 묶음 순서(최근 → 과거)대로("지난 {per}에는 …"). 사실 토큰은 쓰지 않는다(D-54 보완). 흐름 사실(`revenue_yoy_run`, `operating_loss_run`)은 지금도 이어지는 상태이므로 여기 쓰지 않고 `sales_profit`에서 현재형으로 쓴다([D-45](../decisions/D-41-D-53.md)). 이력 신호가 여러 개면 같은 기간끼리 한 문장에 묶어 쓴다 — 신호마다 새 문장을 만들면 상한(3문장)을 넘기 쉽다([D-51](../decisions/D-41-D-53.md)). 서로 다른 기간이 3개 이상(상한과 같거나 넘음)이면 서두 문장 없이 기간당 정확히 한 문장만 쓰고, 그래도 넘으면 가장 오래된 기간부터 개수만 언급해 뭉친다([D-52](../decisions/D-41-D-53.md)) | 3문장 |

- **관계 서술 ([D-55](../decisions/D-54-D-59.md))**: AI가 쓰는 관계(증감·흑자/적자·대소·시간 순서)는 코드가 입력에 준 관계뿐이고, 각 관계에는 **자기 종류의 근거**가 같은 문장에 있어야 한다. 목록 밖의 관계는 쓰지 않고 두 값을 차례로 적기만 한다(비교는 읽는 사람이 한다).

  | 관계 | 같은 문장의 근거 | 쓰는 방법 |
  |---|---|---|
  | 증감(R1) | 변화량 사실·`revenue_yoy_run`의 부호, 신호 유형별 산술 방향(매출·영업이익률 신호는 방향대로, 부채비율 급등은 높아짐) | 근거와 같은 방향의 증감 어휘(늘다·줄다·높아지다·낮아지다·증가·감소) |
  | 영업이익 증감(R2) | `relations`의 방향 관계와 두 영업이익 토큰(둘 다 같은 문장) | 그 방향의 증감 어휘. 관계가 없으면(둘 다 적자 등) 값만 |
  | 흑자·적자(R3·R4) | 상태·전환 사실 토큰 | 토큰이 글자를 보여 준다. 글자로 흑자·적자·손실·손해를 쓰지 않는다. 전환은 "바뀌다·돌아서다" |
  | 순이익과 영업이익의 상태 차이(R5) | `relations`의 상태 차이에 걸린 순이익 사실 토큰 | "영업이익과 달리 {…}" |
  | 자본총계 < 자본금(R6) | 활성 자본잠식 배지 | 배지와 두 사실을 한 문장에 |
  | 이어짐(R7) | 흐름 사실 토큰 | "영업적자가 {…}째 이어지고 있어요"("영업적자"는 이 문장에서만 글자로), "매출 감소가 {…}째 이어지고 있어요" |
  | 시간 순서(R8) | `history`의 기간 토큰(입력 순서) | "지난 {per}에는", "그보다 앞선 {per}에는". 시간 어휘는 `history`에서만 |
  | 나란히 놓기(R9) | 절마다 자기 근거 | "{sig.S1} 매출은 {…}로 전년 같은 분기보다 늘었지만, {sig.S2} 영업이익률은 {…}로 낮아졌어요". 배지 하나로 두 지표의 증감을 말하지 않는다. **앞머리 배지 뒤 같은 절에는 그 신호 지표의 사실 토큰이 와야 한다**([D-58](../decisions/D-54-D-59.md), 규칙 14 확장) — 배지만 쓰고 사실을 다른 절로 미루지 않는다 |

  - 늘 쓰지 않는 관계: 비슷함·같은 수준, 신호 없는 정도 표현(훨씬·폭), 정도를 줄이는 표현(조금·약간·살짝, [D-58](../decisions/D-54-D-59.md)), 서로 다른 지표 사이의 크기 비교(예외 R6), 적자끼리의 크기 변화("적자 폭").
  - 서로 다른 지표를 "(으)로"로 잇지 않는다("영업이익은 {…}로 영업이익률은 {…}였어요"가 아니라 쉼표로 차례로). "로"는 같은 지표의 값과 그 비교를 이을 때만 쓴다. 검증기가 확인한다([D-58](../decisions/D-54-D-59.md)).
  - 평가어(개선·악화·좋아지다·나빠지다)는 방향이 같은 신호 토큰이 있는 문장에서만 쓴다. 좋고 나쁨은 신호에만 있다(§3.9).
  - "~때문에", "~덕분에", "~로 인해" 같은 원인 서술은 쓰지 않는다.
- 엇갈리는 묶음에 종합 판정("전체적으로 좋아졌다")을 붙이지 않는다.
- 반복 방지: 같은 사실 토큰은 결과 전체에서 한 번만, 같은 신호 참조는 최대 두 번(개요 1회 + 그 신호의 섹션 1회). 사실표를 차례로 읊지 않고, 신호 묶음의 사실과 섹션 핵심 수준 사실만 쓴다. 개요 사실은 코드가 다른 섹션과 겹치지 않게 지정한다(`sectionFacts.overview`, [D-54](../decisions/D-54-D-59.md)).
- 신호는 코드가 정한 `section`에서 쓴다. 활성 신호는 발생 기간이 과거여도(상태 신호, 같은 회계연도의 부채비율 급등) 현재형으로 주제 섹션에서 쓴다. `history`에는 이력 신호만 있다([D-54](../decisions/D-54-D-59.md)).
- 변화가 없을 때: 강도 표현 없이 수준을 담담하게 쓴다. 변화가 없다는 사실 자체가 정보다. 상태(STATE) 신호(영업적자 지속·자본잠식)는 `changeStatus`가 NONE이어도 신호 자체는 활성 사실이지만, "지속"·"잠식" 단어는 강도 표현 금지에 걸린다 — 흐름 사실이나 사실 비교("자본총계가 자본금보다 적어요")로 그 단어 없이 서술한다([D-51](../decisions/D-41-D-53.md)). 자본 비교는 활성 자본잠식 신호가 있을 때만, 배지와 같은 문장에 쓴다(그때만 두 사실이 배정된다, [D-54](../decisions/D-54-D-59.md)·D-55 R6). 이 사실 비교에 쓰는 사실(`total_equity`·`capital_stock` 또는 `operating_loss_run`)이 `facts`에 없으면(예: 재무상태표 불일치로 `unavailable`) 비교 문장을 만들지 않고 신호 참조만으로 쓴다 — 사실을 지어내 대신 채우지 않는다([D-52](../decisions/D-41-D-53.md)).
- 데이터 한계: AI는 한계를 설명하지 않는다. `unavailable`·`doNotMention`의 지표를 언급하지 않고, 한계 문구는 코드가 정적 콘텐츠로 섹션 옆에 표시한다.
- 문체는 §8 스타일 가이드(초등 고학년, 짧은 문장, 해요체). 전문용어 툴팁은 코드가 단다.

#### 4.4.4 출력 계약 (AI)

```
{ "overview": string, "sales_profit": string|null, "structure": string|null, "history": string|null }
```

- `sections`에 있는 섹션은 비어 있지 않은 문자열, 없는 섹션은 null이다.
- 글 안의 토큰: `{fin.<지표>.<기간 키>}`(사실), `{per.<기간 키>}`(기간 라벨), `{sig.S<n>}`(신호). 숫자(연도·분기 포함)는 토큰 밖에 쓰지 않는다. 마크다운·링크를 쓰지 않는다.
- 코드는 토큰을 값 스냅샷으로 바꿔 렌더링한다. `{sig}`는 신호 유형의 정적 이름(예: "매출 큰 폭 감소") 배지로, 누르면 최근 변화 타임라인의 그 신호로 간다. 흑자·적자 상태·전환 사실도 다른 사실처럼 스냅샷의 표시 값(닫힌 문구)으로 바뀐다.
- 렌더링 결과는 전체가 HTML 이스케이프된다 — 토큰 값뿐 아니라 토큰 사이의 AI 문장도 외부 입력으로 다룬다(2026-09-27 보안 점검, work/3-4-verification-2.md §7.4.28).

`analysis` 행(architecture.md §4.2)에 저장한다.

| 필드 | 내용 |
|---|---|
| 결과 JSON | AI 출력 그대로(토큰 포함) |

| 시도 기록 | 시도마다 결과(통과·거절·JSON 파싱 실패·잘림/거절·호출 실패), 실패 규칙, 파싱한 출력, 파싱 실패 원문, 검증기 버전. 거절된 결과도 남긴다(원인 분석·검증기 변경 뒤 재판정용). 게시·렌더링·무효화는 읽지 않는다([D-53](../decisions/D-41-D-53.md)) |

- 표시 값: AI 문장의 토큰은 값 스냅샷의 **원값·단위·통화**로 렌더링할 때 서식을 만든다(저장된 표시 문자열은 감사용이고, 단위를 모를 때만 쓴다, [D-41](../decisions/D-41-D-53.md)·[D-56](../decisions/D-54-D-59.md)). 비율은 수준에 '+'를 붙이지 않고 변화량(`_yoy`의 %, %p)에만 부호를 붙인다.
- 조사: 토큰 바로 뒤의 조사(으로/로, 이었/였, 이에요/예요, 을/를, 은/는, 이/가, 과/와)는 렌더러가 렌더링 값의 끝소리에 맞춘다(D-56). AI가 어느 쪽을 써도 된다.
- 문장 목록: 렌더러는 섹션 글을 검증기와 같은 문장 경계로 나눈 목록도 준다. 화면은 문장마다 줄을 바꾼다(D-56).
- 근거 연결: 섹션마다 쓴 사실 토큰의 기간을 모아 "근거: 반기보고서(2026.06, 공시 링크)"를 코드가 붙인다. 신호 배지는 근거 공시번호로 연결한다. 공시 링크는 공시번호로 코드가 만든다(D-31 묶음의 최신본).
- 헤더(코드): 기준(연결/별도), 통화(비원화는 "원화로 바꾸지 않은 값" 안내), 설명 기준 기간, AI 생성 표시, 면책 문구. 기준·통화·설명 기준 기간은 스냅샷 값, 최신 재무 기간과 데이터 한계 문구는 렌더링 시점의 현재 값이다([D-42](../decisions/D-41-D-53.md)).
- 섹션 옆 참고(코드): 그 섹션 지표에 해당하는 제한 코드의 정적 문구(예: "은행·보험 같은 금융회사는 부채비율로 재무 구조를 보지 않아요").

#### 4.4.6 대상·시점·지문·무효화

- 대상: AI 적용 대상(`company.ai_covered`)과 골든셋 목록(설정). 재무 보고서가 없는 기업은 만들지 않는다(화면은 코드 숫자만).
- 시점: 분석 동기화 실행(§6.1)에서, 재무 신호 계산 뒤. 최소 재생성 간격은 없고 예산 우선순위(§6.2)를 따른다.
- 지문 ([D-40](../decisions/D-01-D-40.md), [D-42](../decisions/D-41-D-53.md)): 입력에 쓴 보고서 공시번호 집합 + 입력 신호의 (자연키, 상태, 방향, 심각도, 규칙 버전) + `unavailable` 항목(지표·사유) 집합 + 입력 구성 버전. 정렬해 이어 붙인 문자열의 해시. 값·표시 형식·데이터 한계 신호 코드는 넣지 않는다.
- 같은 지문의 게시·숨김 결과가 있으면 건너뛴다(§6.1). 입력을 만들 때마다 같은 순서·같은 형식이 나와야 한다(결정적 입력).
- 무효화 ([D-42](../decisions/D-41-D-53.md)): 화면을 그릴 때 게시본의 값 스냅샷이 **참조한 것만** 확인한다. 참조한 신호가 철회되었거나 방향이 바뀌었으면, 또는 참조한 사실의 기간·기준 보고서의 현재 공시번호가 스냅샷과 다르거나 보고서가 없으면 AI 설명을 내리고 "재무 자료가 바뀌어 설명을 다시 만드는 중이에요"를 보여 준다. 새 보고서 도착, 신호의 활성→이력 전환·심각도 변경, 규칙 버전 변경, 시계열 기준 전환, 데이터 한계 변화만으로는 내리지 않는다(기준 기간을 표시하므로). 판정은 스냅샷의 자연키·기간·기준으로 현재 신호 상태와 공시번호만 조회하며 입력을 다시 만들지 않는다.

- 첫 게시본이 없는 기업은 AI 설명 없이 코드가 만든 숫자·차트·신호만 보여 준다.

#### 4.4.8 골든셋과 사람 검토

- 재무 쉬운 설명 골든셋(§8의 20개와 겹쳐도 됨)은 아래 경우를 모두 포함한다: 변화 없음, 같은 방향 신호 묶음, 방향이 엇갈리는 묶음, 흑자·적자 전환, 영업적자 지속 + 자본잠식, 부채비율 급등, 금융형(은행·보험·증권), 비원화, 3월·6월 결산, 기준 전환, 결산기 변경, 재무상태표 불일치, 최신 보고서가 사업보고서인 경우, 최근 정정으로 신호가 철회된 경우.
- 골든셋 입력은 로컬 DB에서 만든 §4.4.2 입력 JSON을 저장소에 고정해 둔다(공개 재무 수치만 들어 있다). 프롬프트·모델을 바꾸면 같은 입력으로 다시 생성해 비교한다.
- 사람 검토 항목: 사실 일치(토큰 치환 후 문장이 사실표와 맞는가), 없는 비교·계산이 없는가, 원인·판정·미래 서술이 없는가, 같은 내용 반복이 없는가, 초등 고학년이 읽고 "무엇이 언제 얼마나 변했나"를 말할 수 있는가, 코드의 한계 문구와 충돌하지 않는가.
- 게시 조건: 골든셋 전체가 자동 검증을 통과하고(재시도 포함), 사람 검토에서 사실 오류·금지 표현 0건. 통과 전까지는 초안으로만 저장한다([D-39](../decisions/D-01-D-40.md)).
- 운영 중: 정기보고서 제출 기한 뒤마다 게시본 10건을 무작위로 골라 같은 항목으로 검토하고 결과를 기록한다. 자동 검증 오탐·미탐 사례는 사전·패턴에 반영한다.

#### 4.4.9 확장: 새 지표와 현금흐름 ([D-50](../decisions/D-41-D-53.md), 설계 확정·미적용)

골든셋 사람 검토(§4.4.8)를 마친 뒤 적용한다. 그 전까지 §4.4.1~§4.4.8이 기준이다. 사람 검토는 2026-09-27에 마쳤다(work/3-4-verification-2.md §7.4.35). 다만 적용 전에 아래 `cash_flow` 작성·검증 규칙을 D-55 계약으로 다시 정해야 한다(work/4-financial-metrics-expansion.md §9.7 6)).

- **새 지표(ROE, 유동비율)는 입력에 넣지 않는다.** 화면의 지표 보기(§3.9)가 보여 준다. 넣는 조건은 (1) 그 지표를 쓰는 신호가 생기거나, (2) 골든셋 사람 검토에서 그 지표 없이는 상태를 설명할 수 없다고 확인될 때다. 넣을 때는 사실표에 키만 추가하고 출력 계약은 바꾸지 않는다.
- **현금흐름 사실** (일반형, [D-48](../decisions/D-41-D-53.md)의 정합성 통과 시)

| 사실 키 | 기간 |
|---|---|
| `operating_cf`, `operating_cf_prior`, `investing_cf`, `financing_cf` | 최신 보고서의 누적 기간(분기·반기) 또는 연간. 누적 기간은 분기와 다른 기간 키 종류를 쓰고 라벨은 "2026년 1~6월"처럼 누적으로 보인다 |
| `operating_cf` | 최근 사업연도(연간) |

- 계산하지 않은 현금흐름 지표는 `unavailable`에 사유(`NOT_APPLICABLE_FORMAT`, `ACCOUNT_MISSING`, `CF_NOT_COLLECTED`, `CF_PENDING`)와 함께 넣는다. 지문에는 `unavailable` 집합으로 반영된다([D-42](../decisions/D-41-D-53.md)).
- `FIN_CASH_PROFIT_GAP`을 켜면 신호로 넣고 새 주제 묶음 `CASH`에 둔다. 신호 유형 → 사실 키: `operating_cf`(당기·전기 연간), `operating_income`(연간).
- **선택 섹션 `cash_flow`**: 현금흐름 사실이 있을 때만 코드가 `sections`에 넣는다(`structure` 뒤, `history` 앞). 사실은 D-54의 원칙대로 코드가 `sectionFacts.cash_flow`에 상한(3개) 이하로 배정한다. 2문장, 사실 토큰 3개 이하. 출력 계약은 `{ …, "cash_flow": string|null }`으로 넓힌다(스키마 버전 올림, §4.1 스키마 호환 규칙).
- **작성 규칙**: 영업활동 현금흐름의 부호와 전년 같은 기간 값을 쓴다. 영업이익과는 나란히 놓기만 한다("이익은 났지만 영업으로 들어온 현금은 마이너스였어요"). 원인(재고·매출채권 등)은 입력에 없으므로 쓰지 않는다. 투자·재무활동은 돈이 들어왔는지 나갔는지만 쓴다(무엇에 썼는지는 입력에 없다).
- **검증**: 규칙 6에 현금 어휘(들어오다·들어왔다 / 나가다·빠져나갔다)와 부호의 일치를 더한다. 규칙 9의 금지 주제는 "사실표에 없는 주제"로 일반화한다(현금흐름·ROE는 사실표에 있을 때만 허용. PER·PBR·주가·시가총액·배당은 계속 금지, [D-49](../decisions/D-41-D-53.md)). 규칙 7: `cash_flow`에는 이력 신호를 쓰지 않는다.
- **바뀌지 않는 것**: 토큰 문법, 기존 네 섹션의 규칙·상한(D-39·D-45·D-46), 지문 구성과 참조 기반 무효화(D-42). 현금흐름 사실의 출처 공시번호는 같은 정기보고서 공시번호다. 입력 구성 버전·프롬프트 버전·스키마 버전을 올린다.
