# 4단계 재무 지표 확장 (설계 확정, 구현 전)

> 원본: `implementation-plan.md` §9 (2026-09-27 분리). 이 파일의 § 번호는 원본 번호를 그대로 쓴다. 번호와 파일의 대응은 [문서 지도](../README.md#4-옛-참조와-새-위치).

## 9. 재무 지표 확장: 재무제표와 주요 지표 (설계 확정 2026-09-26, 구현 전)

기업을 이해하는 데 필요한 재무제표와 주요 재무 지표를 현재 설계에 더하는 범위를 정했다. 새 서비스가 아니라 기존 재무 섹션·신호·재무 쉬운 설명의 확장이다. 결정은 [D-47](../decisions/D-41-D-53.md)(지표 범위와 지표 보기), [D-48](../decisions/D-41-D-53.md)(현금흐름 데이터), [D-49](../decisions/D-41-D-53.md)(밸류에이션), [D-50](../decisions/D-41-D-53.md)(AI 설명 확장)에 남겼다. 코드는 바꾸지 않았다.

### 9.1 확인한 사실 (2026-09-26)

**현재 구조**
- `FinancialSummary`는 12분기(`QuarterEntry`)와 3개 사업연도(`AnnualEntry`)의 매출·영업이익·순이익·자산·부채·자본·자본금을 `MetricValue(당기, 전기)`로 가진다.
- 지표는 `FinancialRatios`와 신호 계산기·AI 입력 구성기가 나눠 계산한다. 지표 이름·단위·사유를 한 곳에서 정한 목록은 없다.
- 주요계정 API로 이미 저장하지만 쓰지 않는 계정: 유동자산(26,734행)·유동부채(26,733행)·비유동자산·비유동부채·이익잉여금·법인세차감전 순이익·총포괄손익.
- 사업보고서 행에는 전전기 금액(`prior2_amount`)이 있다. 그래서 전년 ROE의 기초 자본까지 같은 보고서에서 얻는다.

**기존 데이터로 본 새 지표** (ACTIVE 2025 사업보고서 2,528벌, 연결 우선)
- ROE 입력 있음 2,509벌. 기초·기말 자본 중 하나가 0 이하인 보고서 29벌.
- ROE 중앙값 2.9%, 음수 942벌(37%), 절댓값 100% 초과 50벌(그중 잠식 23벌).
- 유동비율 입력 2,472벌, 중앙값 1.67배.

**전체 재무제표 API (`fnlttSinglAcntAll`, 실제 호출 약 320건)**
- 응답은 보고서당 85~349행(재무상태표·손익·포괄손익·현금흐름표·자본변동표)이고, 현금흐름표는 약 30~50행이다.
- 반기(2026.06) 무작위 40개사 + 지정 5개사(금융형 포함): 현금흐름표 45/45. 영업·투자·재무활동 합계의 표준 ID 45/45. 지배기업 소유주지분(자본)은 연결 전부에 있었다. 지배주주 순이익은 연결 3개사에서 표준 ID로 오지 않았다. 기본주당이익은 2개사에서 없었다.
- 반기 무작위 120개사: 공시번호가 저장된 주요계정 보고서와 120/120 같았다. 세 합계 119/120.
- 2025 사업보고서 무작위 150개사: 공시번호 150/150, 세 합계 150/150, 기말 현금 148/150.
- 분기·반기 현금흐름 `thstrm_amount`는 회계연도 누적이고, 전년 같은 누적은 `frmtrm_q_amount`에 있다. 예: 삼성전자 2025년 3분기 영업활동 현금흐름 56.5조 = 9개월.
- 사업보고서는 `thstrm`·`frmtrm`·`bfefrmtrm`에 3년치가 있다.
- 세부 행은 믿기 어렵다. 삼성전자 반기 현금흐름표의 "반기순이익" 행은 2분기 3개월 값이었다. 표준 ID가 없는 행이 보고서마다 0~50개였다.

**현금흐름 분포** (일반형)

| 기준 | 영업활동 현금흐름 < 0 | 영업이익 > 0인데 영업활동 현금흐름 < 0 | 전년 같은 기간 대비 부호 전환 |
|---|---|---|---|
| 2026 반기 누적 (117개사) | 45 (38%) | 19 / 84 (23%) | 33 (28%) |
| 2025 연간 (147~148개사) | 49 (33%) | 1년 13 / 95 (14%), 2년 연속 6 / 147 (4%), 3년 연속 2 | 37 (25%) |

금융형 표본(NH투자증권)은 영업활동 현금흐름이 3년 연속 −1.2조~−5.4조였다. 고객 자금 흐름이 섞인 값이다.

### 9.2 범위 판단

| 후보 | 판단 | 이유 |
|---|---|---|
| 매출·영업이익·순이익·영업이익률·부채비율·자본잠식 | 유지 | 기존 지표·신호(D-35) |
| ROE (연간) | **추가** | 자본 대비 이익은 영업이익률과 다른 정보다. 금융형의 유일한 수익성 지표다. 같은 사업보고서 안에서 계산된다 |
| 유동비율 | **추가** (일반형) | 단기 지급 여력은 부채비율과 다른 정보다. 데이터가 이미 있다 |
| 현금흐름 세 합계, 기말 현금 | **추가** (일반형) | 이익이 현금으로 들어왔나는 새 관찰 수단이다(product.md §7). 새 수집이 필요하다(D-48) |
| 이익·현금흐름 엇갈림 신호 | 후보, 분포 확인 뒤 켬 | 연간 2년 연속 약 4%. 반기·부호 전환은 잡음 |
| 순이익률, ROA, EPS, BPS | 제외 | 이미 있는 값을 다른 분모로 나눈 것이다 |
| 잉여현금흐름, 현금흐름 세부 항목 | 제외 | 정의가 여러 가지이고 세부 행 품질이 낮다 |
| 분기 ROE, 최근 4분기 합산 지표, 분기 단독 현금흐름 | 제외 | 보고서를 넘나드는 계산(D-33·D-35) |
| PER, PBR, 시가총액, 배당수익률 | 제외 | 시장 가격이 필요하고 가치 판정으로 읽힌다(D-49) |
| 지표 수준 평가, 종합 점수·등급 | 제외 | 판단 대행(product.md §10) |

### 9.3 기존 구조를 쓰는 방법

| 구성 요소 | 확장 |
|---|---|
| `financial` (요약) | 기간에 유동자산·유동부채를, 연간에 ROE 입력(전전기말 자본)을 더한다. 현금흐름은 누적 기간이라 분기 기간과 섞지 않고 기간별 목록으로 따로 둔다. 지표 이름·단위·기간 종류·비교 방식·적용 형식·사유 코드를 **지표 목록 한 곳**에 두고, 화면·신호·AI 입력이 같이 쓴다(spec/analyses.md §4.1의 "지표 목록"을 코드로 만든다) |
| `signal` | 계산기·상태 전이(D-36)·재판정(D-43)은 그대로다. `FIN_CASH_PROFIT_GAP`을 켤 때 유형과 규칙 버전만 추가한다 |
| `analysis` | 단계 C 전까지 바꾸지 않는다. 단계 C는 사실 키와 선택 섹션 하나만 더한다(D-50) |
| 화면 (4단계) | 지표 보기(spec/signals-financial.md §3.9)를 코드가 만든다. 정의·해석 참고·사유 문구는 정적 콘텐츠(`content_entry`)다 |
| 수집 | 현금흐름 수집 작업을 재무 수집과 신호 계산 사이에 둔다. 체크포인트는 보고서 단위이고 계기는 재무 수집과 같다 |

### 9.4 구현 단계

**단계 A — 새 수집 없음 (화면 4단계와 함께 진행 가능)**
1. 지표 목록(코드): 기존 지표와 ROE·유동비율의 키·이름·단위·기간 종류·비교 방식·적용 형식·사유 코드를 둔다. `FinancialRatios`의 공식을 옮기지 말고 참조한다.
2. 요약 확장: 유동자산·유동부채, 연간 전전기말 자본총계.
3. 지표 보기 모델: 값·비교·산술 방향·연결 신호·사유. 정의·해석 참고 문구의 초안을 만든다(정적 콘텐츠, 사람 검토). 판정 표시는 D-60, 지표별 비교·연속 수·자본잠식 상태는 D-61, 표시(기간 라벨·기준·부호)는 D-62를 따른다. 변화 신호의 지속 값이 설계(spec/signals-financial.md §3.7)와 다른 구현 불일치를 이 단계 전에 설계 쪽으로 맞춘다(D-61). → 2026-09-27 맞췄다(§9.7 끝, 규칙 `fin-3`).
4. 테스트는 §9.5를 따른다. AI 입력·신호는 바꾸지 않는다(골든셋 입력이 그대로여야 한다).

**단계 B — 현금흐름 수집 (D-48)**
1. 마이그레이션으로 현금흐름표 보고서·행 테이블을 만든다.
2. OpenDART 클라이언트에 전체 재무제표 호출을 추가한다. 인증키·URL 로깅 규칙은 기존과 같다.
3. 수집 작업:
   - 정기공시 계기로 받는다. 연결/별도는 그 보고서에 연결이 있으면 연결이다.
   - 초기 적재는 기업마다 최신 사업보고서와 그 뒤 분기·반기 보고서(약 1만 호출)를 하루 한도 안에서 나눠 받는다.
   - "데이터 없음"은 반복 요청하지 않는다.
4. 요약·지표 보기에 현금흐름을 더한다. 정합성(공시번호·통화 일치) 검사와 금융형 제외를 넣는다.
5. 전체 적재 뒤 분포를 기록한다: 표준 ID 누락률, 연간 엇갈림 1년·2년·3년 비율, 크기(매출 대비) 분포. 이 결과로 `FIN_CASH_PROFIT_GAP`을 켤지와 크기 조건을 정하고 규칙 버전을 올린다. 켜지 않으면 이유를 기록한다.

**단계 C — 재무 쉬운 설명 확장 (D-50, 골든셋 사람 검토 뒤)**
- 현금흐름 사실, 누적 기간 키·라벨, 선택 섹션 `cash_flow`, 검증 규칙 6·7·9 확장을 적용한다. 스키마·입력 구성·프롬프트 버전을 올린다.
- 골든셋에 현금흐름 경우를 더한다: 이익·현금 엇갈림, 영업현금흐름 부호 전환, `CF_PENDING`, 금융형.

**하지 않는 것**: 밸류에이션 지표, 시세 연동, 동종업계 참고 값(동종업계 정의 구현 뒤), 지배주주 기준 ROE, 현금흐름 세부 항목·잉여현금흐름, 새 지표의 AI 입력(D-50의 조건 전), 신호 문턱값 변경.

### 9.5 테스트할 경계 조건

| 대상 | 경계 조건 |
|---|---|
| ROE | 기초·기말 자본 모두 양수 → 계산. 어느 하나 0 또는 음수 → `EQUITY_NOT_POSITIVE`. 순손실 → 음수 ROE 그대로. 전전기말 자본 없음 → 당기 ROE만 있고 전년 ROE와 비교 없음. 12개월이 아닌 회계연도 → `IRREGULAR_PERIOD`. 금융형 → 계산. 비원화 → 계산(비율) |
| 유동비율 | 금융형 → `NOT_APPLICABLE_FORMAT`. 유동부채 0 → 계산 안 함. 재무상태표 불일치 기간 → 제외. 전기말 대비 차이(%p) 부호 |
| 현금흐름 기간 | 1분기·반기·3분기 값은 누적이고 라벨도 누적(예: "1~6월"), 전년 같은 누적과만 비교. 4분기 파생 없음. 사업보고서 한 벌로 3년 연간. 3월·6월 결산의 누적 라벨 |
| 현금흐름 정합성 | 공시번호 같음 → 사용. 공시번호 다름(정정 시차) → `CF_PENDING`, 신호·AI 사실 없음. 통화 다름 → `CF_PENDING`. 표준 ID 없음(비슷한 이름 행이 있어도) → `ACCOUNT_MISSING`. 아직 수집 전·초기 적재 범위 밖 → `CF_NOT_COLLECTED`. 금융형 → `NOT_APPLICABLE_FORMAT` |
| 현금흐름 수집 | 보고서에 연결이 있으면 연결만 호출, 별도만 있으면 별도. 정정 공시 → 다시 받아 행 교체. 데이터 없음(013) → 반복 요청 안 함. 한도 초과(020) → 실행 중단. 인증키·URL이 로그·예외에 없음 |
| 엇갈림 신호 (켤 때) | 당기·전기 모두 영업이익 > 0 & 영업활동 현금흐름 < 0 → 성립(낮음). 전전기까지 → 중간. 한 해만 → 없음. 영업이익 0 → 없음. 반기 누적으로는 판정 안 함. 다음 사업보고서에서 풀리면 D-36대로 이력 |
| 지표 보기 | 산술 방향: 증가·감소·같음(0). 신호가 없는 변화에 평가 표시 없음. 연결 신호가 있으면 배지. 계산하지 않은 지표는 숫자 대신 사유 문구. 정적 문구에 평가어(양호·위험·우량·저평가 등) 없음(검토 체크리스트) 판정 자리 네 상태(신호 있음·성립하지 않음·판정 대상 아님·판정 규칙 없음, D-60): 비원화 기업의 영업이익률 큰 변화가 "성립하지 않음"으로 보이지 않음(1640형), 전환 신호의 배지가 영업이익률에 붙지 않음. 부호가 바뀌거나 둘 다 음수인 영업이익·순이익에 증감 방향 없음(D-61). 완전잠식(자본총계 ≤ 0)은 잠식률 대신 상태. 부채비율·유동비율에 연속 수 없음. 비12월 결산 분기 라벨이 달로 나옴, 한 값의 표시가 지표 보기·요약 재무제표·AI 설명에서 같음, 증감 어휘와 부호가 겹치지 않음(D-62) |
| AI 확장 (단계 C) | 현금흐름 사실이 없으면 `cash_flow` 섹션 없음. "들어왔다"·"나갔다"와 부호 일치. 현금흐름 사실이 없는데 "현금흐름" 언급 → 실패. PER·PBR·배당 언급 → 실패. 기존 네 섹션의 결과·지문은 현금흐름이 없는 기업에서 달라지지 않음 |

### 9.6 완료 기준

- 단계 A: `./gradlew build` 통과. 기존 골든셋 입력 12개가 바뀌지 않는다. ROE·유동비율 값을 로컬 DB 표본(삼성전자·KB금융·금융형·비원화·잠식 기업)으로 손계산과 대조했다.
- 단계 B: 초기 적재 호출 수·데이터 없음 수·표준 ID 누락률·`CF_PENDING` 수를 기록했다. 분포를 기록하고 엇갈림 신호의 사용 여부를 결정했다. 인증키가 로그·저장소에 없다.
- 단계 C: §4.4.8 골든셋(현금흐름 경우 추가)이 자동 검증을 통과하고 사람 검토에서 사실 오류·금지 표현이 0건이다.

### 9.7 설계 일관성 검토 (2026-09-26, 검토만 — 코드·결정문 변경 없음)

**검토 범위**
- 대상: D-47~D-50, spec/signals-financial.md §3.5~§3.9·§4.4.9, 이 장 §9.1~§9.6.
- 대조한 기준: D-06·D-15·D-17, D-33~D-46, 그 뒤의 D-54·D-55, product.md §4·§10·§11·§12.
- 각 항목에 **[확인]**(문서·코드로 검증)과 **[판단]**(검토 의견)을 붙인다.

**1) 네 요소의 역할 — 겹치거나 섞이지 않는가**

| 요소 | 답하는 질문 | 만드는 곳 | 판정 |
|---|---|---|---|
| 요약 재무제표 | 숫자의 근거는 무엇인가(원천 값) | 코드 | 없음 |
| 지표 보기 | 각 지표가 얼마이고, 비교 기준보다 어떻게 달라졌나 | 코드 + 정적 콘텐츠 | 산술 방향·부호 사실만 |
| 재무 신호 | 규칙상 큰 변화인가, 좋고 나쁨의 방향·심각도는 | 코드(규칙 카탈로그) | 방향·심각도 |
| 재무 쉬운 설명 | 코드가 고른 변화들이 어떻게 함께·어떤 순서로 나타났나 | AI(코드가 준 사실·관계만, D-54·D-55) | 없음 |

큰 틀의 역할 나눔은 일관적이다 [확인]. 다만 섞이거나 겹치는 곳이 다섯 군데 있다.

- **(a) 신호 배지를 "확인 지표"로 연결한다 — 의미가 섞인다** [확인]
  - §3.9는 "이 지표를 확인 지표로 가진 활성 신호가 있으면 신호 배지"라고 한다. D-47은 이 자리를 "규칙상 큰 변화로 판정되었는지 여부"라고 적었다.
  - 그런데 확인 지표의 뜻은 "이 신호가 있을 때 **앞으로 지켜볼** 지표"다(§3.1). 무엇이 변했는지와 무엇을 지켜볼지는 다른 질문이다.
  - 재무 신호는 지금 대체로 두 뜻이 겹친다. 공시 신호가 들어오면 어긋난다. §3.4에서 공급계약 체결의 확인 지표는 매출 증가율, 대규모 시설투자는 매출 증가율·영업이익률, 유상증자는 부채비율이다. 그러면 매출 지표 보기에 "공급계약 체결" 배지가 "규칙상 큰 변화"로 붙는다. 매출은 변하지 않았는데도 그렇다.
  - 코드에는 신호와 지표를 잇는 대응이 이미 두 벌 있다. 신호 계산기의 `watch_metrics`(확인 지표)와, AI 입력 구성기의 신호 → 사실 키 대응(`SIGNAL_FACT_KEYS`, §4.4.2)이다. 같은 "신호-지표 연결"이 두 곳에 다른 뜻으로 있다.
  - [판단] 지표 목록(§9.3)에 신호 유형마다 **근거 지표**(무엇이 변했나)와 **확인 지표**(무엇을 지켜보나)를 따로 둔다. 지표 보기의 배지와 AI 입력의 신호 → 사실 키는 모두 근거 지표에서 만든다.
- **(b) "규칙상 큰 변화로 표시되지 않음" 한 문구가 서로 다른 세 상태를 덮는다** — 3)에서 다룬다.
- **(c) 같은 값이 세 번 나온다** [확인]
  - 요약 재무제표 13행(손익 3, 재무상태 6, 현금흐름 4) 가운데 9행이 지표 보기의 현재 값과 같다. 매출액·영업이익·당기순이익, 자본총계·자본금, 현금흐름 합계 셋과 기말 현금이다.
  - 지표 보기에 없는 것은 유동자산·자산총계·유동부채·부채총계 4행뿐이다. 모두 비율의 재료다.
  - 추이 차트까지 치면 같은 값이 세 번 보인다.
  - [판단] 요약 재무제표는 **근거 표**로 역할을 못 박는다(값과 비교 열만, 방향·배지·해석 없음). 변화의 1차 표시는 지표 보기다. 화면 배치는 화면 설계의 몫이지만 "같은 값에 서로 다른 비교·방향 표현을 붙이지 않는다"는 정보 구조에서 정해 둔다.
- **(d) '같은 방향이 이어진 기간 수'를 세는 곳이 흩어져 있다** [확인: 코드]
  - 설계(§3.1·§3.7)는 변화 신호에도 지속을 계산한다고 적었다. 그러나 구현은 변화 신호 네 종류(매출·영업이익률·전환·부채비율)의 `persistence`를 null로 저장한다. `SignalDraft` 주석도 "상태 신호가 아니면 null일 수 있다"고 적었다. 기존 3-3 구현의 설계-구현 불일치다.
  - 매출 연속 흐름은 AI 입력 구성기(`FactCollector#addFlowFacts`)가 따로 센다.
  - 지표 보기(§3.9)가 "같은 방향이 이어진 기간 수"를 또 만들면 세 번째 계산이 된다. 화면·신호·AI의 숫자가 서로 다를 수 있다.
  - [판단] 연속 계산을 지표 목록에 한 번만 두고 셋이 같이 쓴다. 변화 신호의 지속 null은 이 확장 전에 설계와 구현 중 어느 쪽에 맞출지 정한다. → 2026-09-27 D-61로 정하고 구현했다(이 절 끝).
- **(e) 지표 보기와 AI 설명의 경계 문구가 서로 다르다** [확인]
  - D-47은 "지표 보기: 화면과 AI가 같은 구조를 쓴다", §3.9는 "지표 보기는 코드가 모두 만들고, AI는 관여하지 않는다"라고 적었다.
  - 실제로 둘이 공유하는 것은 지표 목록·값·비교(재무 요약)다. 지표 보기의 정의·해석 참고(정적 콘텐츠)는 AI 입력이 아니다.
  - [판단] 경계를 §4.4.1에 한 줄로 적는다: AI는 지표 정의를 쓰지 않는다. 지표 보기가 이미 보여 주는 지표별 비교를 되풀이하지 않는다(D-54로 배정된 것만 쓴다). AI가 맡는 것은 지표 사이의 관계와 시간 순서(D-55)다.

**2) 지표별 비교 기준과 변화 정보** [확인: 문서 간 대조 / 판단: 권고 표]

§3.9의 "비교"는 모든 지표에 한 가지 틀을 쓴다(변화량 + 산술 방향 "늘었다·줄었다·같다" + 이어진 기간 수). 그런데 §3.6은 지표마다 비교 방식을 따로 정해 두었고, 한 틀을 그대로 쓰면 오해가 생기는 조합이 있다.

- **부호가 바뀌거나 둘 다 음수인 값**(영업이익·순이익·현금흐름)
  - 예: "−28.4억원 → −4.5억원, 늘었다".
  - D-55는 AI에게 이 표현(적자끼리의 크기 변화)을 금지했다. 산술적으로는 맞지만 손실에 대한 말로 읽히기 어렵다는 이유였다. 같은 이유가 화면에도 그대로 적용되는데, 틀을 그대로 쓰면 화면에는 이 문구가 나간다.
- **재무상태 지표의 "전기말"**
  - 분기 보고서의 전기말은 **직전 사업연도 말**이다(같은 보고서 비교, D-33).
  - 분기마다 같은 기준점과 비교하므로 "이어진 기간 수"를 세면 같은 변화를 여러 번 센다.
  - 누적 현금흐름(1~3월, 1~6월, 1~9월)도 기간이 겹쳐 연속 계산의 뜻이 없다.
- **잔액 지표의 기준점이 서로 다르다.** 기말 현금은 현금흐름표의 비교 열이라 "전년 같은 기간 말"과 비교하고, 부채비율·유동비율은 "직전 사업연도 말"과 비교한다. 한 화면의 잔액 지표 두 종류가 다른 기준점과 비교된다.
- **한 묶음 안에 기간이 섞인다.** ROE는 연간만 있다. 최신 기간이 분기인 기업에서는 수익성 묶음에 "영업이익률 2026년 2분기"와 "ROE 2025년"이 함께 놓인다.
- **유동비율 단위가 문서마다 다르다.** D-47·§9.1은 "중앙값 1.67배", §3.6은 "(%)"와 "%p"다. 부채비율과 같은 %로 맞추는 편이 일관적이다.

**3) 판단할 수 없는 상태를 정상 상태로 다루는가**

잘 되어 있는 것 [확인]
- 사유 코드가 넉넉하다(`ACCOUNT_MISSING`, `BASE_NOT_POSITIVE`, `SMALL_BASE`, `NOT_APPLICABLE_FORMAT`, `NON_KRW`, `EQUITY_NOT_POSITIVE`, `IRREGULAR_PERIOD`, `BASIS_GAP`, `DERIVED_INVALID`, `INCONSISTENT_BALANCE`, `CF_PENDING`, `CF_NOT_COLLECTED`).
- "추정하거나 빈칸으로 두지 않고 계산하지 않음과 사유를 보여 준다"는 원칙이 있다(§3.9).
- 신호 방향에 "불확실"이 있다(§3.1). 기업 전체의 한계는 데이터 한계 신호로 다룬다.

빈 곳
- **사유가 지표 단위 하나뿐이다** [확인]
  - 지표 보기의 사유 자리는 "계산하지 않음" 하나다. 실제로는 부분마다 사정이 다르다.
    - 값은 있는데 비교가 없다: ROE의 전전기말 자본 없음, 12개월이 아닌 회계연도, 4분기 파생값, `BASIS_GAP`.
    - 값과 비교는 있는데 증가율만 없다: `SMALL_BASE`.
    - 값과 비교는 있는데 규칙 판정 대상이 아니다: 비원화·금융형의 매출 신호.
  - [판단] 사유를 **값·비교·판정** 세 자리에 따로 둔다.
- **신호 자리의 상태가 둘뿐이다** [판단]
  - 신호 자리에 들어갈 수 있는 상태는 실제로 넷이다.
    1. 신호 있음(배지)
    2. 판정했고, 큰 변화가 아님
    3. 이 기업은 판정 대상이 아님(사유: 금융형·비원화·기준값 미만·불일치)
    4. 이 지표에는 판정 규칙이 없음(ROE·유동비율·순이익·기말 현금, 엇갈림 신호를 켜기 전의 현금흐름)
  - 지금의 한 문구("규칙상 큰 변화로 표시되지 않음")는 3·4에서 사실이 아니다. 판정을 하지 않았는데 판정한 것처럼 읽힌다. 네 상태를 나눠 표시한다.
- **이름 없는 사유가 있다** [확인]
  - 유동부채 ≤ 0(§3.6)과 ROE 비교 기간 없음(§9.5)은 사유 코드 이름이 없다. 이름을 정한다.
- **"불확실" 방향을 표시하는 코드 경로가 없다** [확인: 코드]
  - 설계는 방향을 긍정·부정·불확실 세 값으로 정했다(§3.1). 그런데 코드의 배지 표(`StaticContent.badgeName`)는 POSITIVE가 아니면 모두 부정 표를 쓴다. 묶음의 `mixedDirection`은 서로 다른 방향 값이 둘 이상이면 true다.
  - 불확실 신호(`FIN_CASH_PROFIT_GAP`)를 켜면 배지가 부정 표로 떨어진다. 같은 묶음에 들어가면 "방향이 엇갈림"으로도 계산된다.
  - D-50은 새 주제 `CASH`로 따로 묶어 뒤의 문제는 피한다. 배지는 단계 B에서 고쳐야 한다.
- **같은 원인을 두 번 말할 수 있다**
  - 데이터 한계 신호(기업 단위)와 사유 코드(지표 단위)가 같은 원인을 말한다. 예: 금융형이면 `FIN_DATA_FINANCIAL_FORMAT`과 `NOT_APPLICABLE_FORMAT`이 함께 있다.
  - §3.9의 나눔(기업 전체는 신호 문구, 지표는 사유)은 맞다. 같은 원인이면 지표 자리에는 짧은 사유만 둔다는 표시 규칙을 화면 설계로 넘긴다.

**4) 업종·상황에 따라 해석이 달라지는 지표**

- 설계는 이미 수준 판정("높다·낮다·양호·위험")과 종합 점수·등급을 금지했다(D-47, §3.9, product.md §10) [확인]. 코드의 판정은 변화(신호)와 부호 사실까지다.
- **남은 위험은 코드가 아니라 정적 문구다** [판단]
  - "해석 참고"에 교과서식 기준이 들어가면, 코드가 금지한 수준 판정이 정적 콘텐츠로 되살아난다. 예: "유동비율 200% 이상이면 안정", "ROE 10% 이상이면 우수", "부채비율 100% 이하 양호".
  - §9.5의 검토 체크리스트는 평가어만 막는다. **숫자 기준·구간·"보통 ~ 이상" 같은 기준 제시 금지**를 더한다.
- **ROE는 자본이 작을수록 크게 나온다** [확인]
  - 절댓값 100% 초과가 50벌이고, 그중 23벌이 자본잠식 기업이다.
  - 수준 판정이 없으니 틀린 판정은 없다. 그래도 큰 ROE가 좋은 성과로 읽힐 수 있다.
  - [판단, 선택] 자본잠식 신호가 활성인 기업은 ROE 해석 참고에 "자본이 작으면 비율이 크게 나온다"는 사실 문구를 코드가 고르게 할 수 있다. 판정이 아니라 조건으로 정해지는 문구 선택이라 D-47 범위 안이다.
- **기존의 절대 수준 조건은 이번에 바꾸지 않는다**
  - 부채비율 급등의 "기간 말 200% 이상"은 변화 신호의 문턱일 뿐 수준 평가로 표시하지 않는다(D-35).
  - 업종별 문턱값은 D-35의 재검토 조건(동종업계 정의 구현 때)에 이미 있다.
- 업종 맥락은 동종업계 중앙값을 "참고 값"으로 나란히 두는 방식으로만 준다(D-47) — 아래 5).

**5) 기업 간 비교·순위 — 이번 확장에 필요한가: 아니오** [판단]

- 이번 확장(§9)은 이미 "동종업계 참고 값(동종업계 정의 구현 뒤)"을 하지 않는 것으로 두었다 [확인].
- 이유
  1. **변화 중심 원칙과 맞지 않는다.** 기업 간 비교는 그 기업의 변화가 아니라 위치(수준)다. product.md §4의 일곱 질문에 직접 답하지 않는다. 예외는 "동종업계 대비 성장률 상회·하회" 신호 하나로, 변화를 업계와 견준다.
  2. **순위·백분위는 곧 서열 평가다.** product.md §10(종합 평가 금지)과 D-47에 걸린다.
  3. **전제가 없다.**
     - 동종업계 정의(§3.4)는 확정 경쟁사(기업 이해 분석, 미구현)나 산업코드 중분류에 기댄다. 중분류 64는 은행(금융형)과 지주회사(64992, 대부분 일반형)를 한데 묶는다.
     - 표본 5개 이상에, 형식·결산월·통화·기간도 맞춰야 한다.
  4. **비교 값이 계속 바뀐다.** 업계 값은 바뀌므로 값 스냅샷(D-25)과 무효화까지 설계가 따라온다.
- 권고
  - §9.4의 "하지 않는 것"에 **순위·백분위·업종 내 위치 표시**를 명시한다. 동종업계 정의를 구현한 뒤에도 순위는 만들지 않는다. D-47의 "순위·평가어는 붙이지 않는다"를 지표 보기 전체로 넓히는 것이다.
  - 업계 비교 신호, 중앙값 참고 값, 경쟁사 비교(`pair_compare`)는 동종업계 정의 단계의 별도 결정으로 둔다.
  - AI 적용 대상 선정의 매출 순위(D-23)는 내부 선별이고 화면에 나가지 않으므로 해당하지 않는다.

**D-50·§4.4.9의 `cash_flow` 규칙과 D-55의 충돌** [확인]
- **검증 방식**
  - §4.4.9는 "규칙 6에 현금 어휘(들어오다·나가다)와 부호의 일치를 더한다"고 적었다.
  - D-55는 부호로 정해지는 상태(흑자·적자)를 사전 대조에서 빼고, 코드가 표시하는 상태 토큰으로 바꿨다(R3·R4, 규칙 12).
  - 현금 유입·유출은 D-47이 "부호로 정해지는 사실"로 묶은 같은 종류다. 같은 방식으로 맞춰야 한다. 사전 방식은 §7.4.19에서 확인한 활용형·동의어·부분 문자열 문제를 다시 만든다.
- **작성 예 "이익은 났지만 영업으로 들어온 현금은 마이너스였어요"의 문제 세 가지**
  1. "이익은 났지만"은 토큰 없는 흑자 서술이다. D-55 규칙 12가 막는 형태다.
  2. 영업이익과의 대조는 코드가 주지 않은 관계다. D-55의 R5(상태 차이 관계)처럼 코드가 "영업이익 흑자 + 영업활동 현금흐름 유출"을 관계로 줘야 한다. 엇갈림 신호가 켜지면 그 신호가 근거가 된다.
  3. 영업이익 토큰은 `sales_profit`에 배정되어 있다. `cash_flow`에서 또 쓰면 규칙 4(같은 사실 토큰은 한 번)와 부딪힌다. 예시가 토큰을 피해 말로 쓴 이유로 보인다.
- [판단] 단계 C 전에 D-50의 작성·검증 규칙을 D-55 계약으로 다시 정한다: 유입·유출 상태 사실, 이익·현금 상태 차이 관계, 규칙 12·13 적용. 단계 C는 원래 골든셋 사람 검토 뒤라 지금 급하지는 않다.

**7) MVP 범위** [판단]

- **단계 A**(지표 목록·ROE·유동비율·지표 보기 모델, 새 수집 없음): 유지한다. 다만 1)~3)의 정보 구조 보완은 단계 A 설계에 넣는다. 지표 목록이 화면·신호·AI의 공통 기준이 되므로, 구현 뒤에 고치면 세 곳을 함께 고쳐야 한다.
- **단계 B**(현금흐름 수집, 새 API·테이블·초기 적재 약 1만 호출): product.md §7이 인정한 새 관찰 수단이라 범위 안이다. 화면(4단계)의 첫 출시를 막지 않도록 단계 A와 이미 분리되어 있다 [확인].
- **줄일 것**
  - "이어진 기간 수"를 뜻이 있는 지표에만 둔다(2)의 표).
  - 순위·백분위를 명시적으로 뺀다.
  - 동종업계 관련은 전부 뒤로 둔다(이미 그렇다).
- **늘리지 말 것**: 지표 추가(순이익률·ROA·EPS·BPS 제외 유지), 지배주주 ROE, 현금흐름 세부 항목.
- **결론**: 범위는 적정하다. 기능을 더할 필요는 없고, 정보 구조의 규칙만 보완하면 된다. 비교 유형, 신호 자리의 상태 넷, 근거 지표 연결, 비교 기준 시점 표시가 그것이다.
